# One Product Flow v3.0 — канонический метод

> **Задача метода — собрать работающую воронку одного продукта (первое касание → покупка) и проверить тестом; диагностика нужна, чтобы строить осмысленно, а не «лечить» бизнес.**
>
> Маршрут внутри единой системы. Берёт глубину из движков Marketing OS (скрининг, 5-7 JTBD-сегментов, полный CJM, 7 осей зрелости, оффер, продажи и удержание) и удерживает дисциплину One Product Flow: проблема первой, силы, уровень Шварца, один источник и один тест. Каждый шаг вызывает существующий движок — маршрут не копирует его методологию.

---

## 1. Главная идея слияния — два движения

У двух систем разные движения. Канонический OPF держит **оба по очереди**:

```text
РАСХОДИМСЯ (диагностика)      →      СХОДИМСЯ (фокус)      →      СОБИРАЕМ      →      ТЕСТ
понять весь продукт:                 выбрать одно:                под выбранное:        одно:
скрининг · 5-7 сегментов ·           1 стартовый сегмент ·        продукт · оффер ·     1 источник ·
конкуренты · 7 осей                  1 уровень · силы клиента     CJM · дожим           1 метрика · 1 порог
```

- **Marketing OS** силён в «расходимся» — раскладывает весь продукт на 5-7 сегментов, полный CJM, 7 осей зрелости.
- **One Product Flow** силён в «сходимся» — из всей картины выбирает один сегмент, один уровень входа, один источник, один тест.

Раньше это были две системы. Теперь одна: сначала диагностируем вширь, потом фокусируем в один проверяемый поток.

---

## 2. Принципы (свод лучшего из обеих)

1. **Один продукт/юнит = одна цепочка** (Agency). Компания (бренд, команда, бюджет, CRM, репутация) — общий контекст, собирается один раз. Несколько продуктов = несколько прогонов.
2. **Генеративно, не шаблонно** (Agency). Скилы кодируют, *как думать*: всё цитирует данные по ID, экономика проверяется на сходимость, барьеры из реальности, вывод полный, есть планка качества.
3. **Два движения** (слияние): диагностика вширь → фокус в одно. Не застревать в «расходимся» (карта без теста = справочник) и не прыгать в «сходимся» без диагностики (фокус на угаданном).
4. **Продуктизация** (OPF): диагностика → спринт → группа → клуб. Метод сам продаётся как лестница.
5. **Цель — собранная воронка одного продукта, а не устранение ограничения** (OPF): диагностика (денежная проблема, где рвётся поток) — вход в сборку и подсказка, что тестировать первым. Начинаем с проблемы, а не с продукта, но на выходе — работающий поток + тест, а не «вылеченное» узкое место.

### Гард-рейлы (общие)

1. Цифры — из учёта (1С/CRM), не прикидка. Нет данных → `[Г]`, не выдавать гипотезу за факт.
2. Метить: **факт / гипотеза [Г] / решение / рекомендация**.
3. «Собрано» ≠ «внедрено» — в баллах зрелости.
4. Приоритет сегмента = функция **текущего ограничения**, не только привлекательности.
5. Барьеры — из **негатива конкурентов + VoC**, не из головы.
6. Кросс-ссылка (сквозная): **негатив конкурента = точка слома (JTBD) = барьер (CJM)**. Один факт в трёх местах; расходятся — ошибка.

## 3. Терминологический контракт

Единственный источник определений → [словарь Marketing OS](../../core/glossary.md). Этот маршрут задаёт место термина в последовательности, но не переопределяет его.

Ключевые связи маршрута:

- [главное ограничение](../../core/glossary.md#term-main-constraint) → его [денежная проблема](../../core/glossary.md#term-money-problem);
- [работа клиента](../../core/glossary.md#term-job) → [сегмент](../../core/glossary.md#term-segment) → [стартовый сегмент](../../core/glossary.md#term-starting-segment) + [анти-сегмент](../../core/glossary.md#term-anti-segment);
- [давление текущей ситуации](../../core/glossary.md#term-push) + [притяжение результата](../../core/glossary.md#term-pull) против [тревоги перехода](../../core/glossary.md#term-anxiety) + [инерции текущего способа](../../core/glossary.md#term-habit);
- [момент слома](../../core/glossary.md#term-trigger-moment) (**когда** — активирует поиск) → [точка слома](../../core/glossary.md#term-breaking-point) (**что** — главный барьер сегмента, из негатива конкурентов) → [барьер шага](../../core/glossary.md#term-step-barrier) (их много, по шагам пути) → [точка перелома](../../core/glossary.md#term-decision-point) (**где** — узел да/нет внутри пути);
- [доказательство для клиента](../../core/glossary.md#term-proof) снижает сомнение покупателя; [доказательство метода](../../core/glossary.md#term-evidence) повышает зрелость элемента Marketing OS.

В новых материалах используются русские рабочие названия. `beachhead` остаётся только историческим alias и частью имени файла `s3-beachhead-forces.md`.

## 4. Канонический каркас — 4 фазы, 11 шагов

Рамка на весь метод: диагностируем вширь → **1 сегмент · 1 уровень входа · 1 источник · 1 тест**.

> **JTBD стоит на двух шагах и значит разное — порядок работа→сегмент, не наоборот.** В S2 JTBD = **работа как ось сегментации** (5-7 работ порождают 5-7 сегментов; сегмент = носитель работы, работа первична). В S3 JTBD = **4 силы на уже выбранном сегменте** (силы давление текущей ситуации/притяжение результата/тревога перехода/инерция текущего способа заполняются на одну конкретную группу, поэтому идут после выбора стартового сегмента). Это не «сегмент → работа»: сегмент выбираем внутри карты работ.

Колонка «движок» = каким скилом/модулем шаг питается.

### ФАЗА 1. ДИАГНОСТИКА — расходимся, понимаем весь продукт

| Шаг | Название | Главный вопрос | Движок | Выход |
|---:|---|---|---|---|
| 1 | Компания/эксперт и текущая ситуация | Активы, экономика, цель — и где **главное ограничение**? | `/company-profile` + `/screening` | профайл (1 раз) + вход по продукту + модель параметров (6 кат.) + записка 6 блоков → ограничение + денежная проблема; конкуренты поверхностно (кто + негатив) |
| 2 | JTBD-карта сегментов | Какие 5-7 работ и **кто** их нанимает? | `/jtbd-segments` | 5-7 сегментов: Core/Big Job, точка слома, опыт А/Б, спрос с объёмами, приоритизация (ядро/быстрые деньги/не первым) |

### ФАЗА 2. ФОКУС — сходимся, выбираем одно

| Шаг | Название | Главный вопрос | Движок | Выход |
|---:|---|---|---|---|
| 3 | Стартовый сегмент + 4 силы | Один сегмент под цель И ограничение, что им движет? | [jtbd-module](jtbd-module-2026-07-06.md) + niche-icp-jtbd | один сегмент + анти-сегмент, давление/притяжение/тревога/инерция, критерии найма/увольнения, голос клиента |
| 4 | Уровень осознанности | На каком уровне Шварца входим? | [schwartz-entry-map](schwartz-entry-map-2026-07-06.md) | один уровень (из доминирующей силы) |

### ФАЗА 3. СБОРКА — проектируем под выбранное

| Шаг | Название | Главный вопрос | Движок | Выход |
|---:|---|---|---|---|
| 5 | Продукт / юнит | Что закрывает эту работу на этом уровне? | niche-icp-jtbd (юнит, 4 уровня ценности) | продукт = проблема+сегмент+силы+уровень+результат+механизм+формат+доказательство+первый шаг; чек/маржа/КФВ |
| 6 | Оффер, упаковка, позиционирование | С кем деремся, где **незанятое место**, что обещаем? | `offer-packaging-design` + competitive-field | незанятое место + стоп-обещания + оффер под уровень, линейка пакетов, снятие риска, CTA |
| 7 | Источник | Откуда один проверяемый поток? | niche-icp-jtbd (канал по механике) | один источник, где сегмент уже есть |
| 8 | CJM | Какой путь касаний и где рвётся? | `/cjm` | путь ~8 шагов: эмоция(балл+лейбл), барьеры, диалог-цитаты, запросы 15+, места поиска, лид-магниты на шаг, точка перелома, green/red, 5 приоритетов |
| 9 | Заявка · квалификация · дожим | Как интерес → оплата → возврат? | `diagnostic-sale` + `follow-up-lost-leads` + `reactivation-old-base` | сценарий заявки, квалификация, доказательство, дожим по контексту |

### ФАЗА 4. ИЗМЕРЕНИЕ И ТЕСТ — сходимся к одному тесту

| Шаг | Название | Главный вопрос | Движок | Выход |
|---:|---|---|---|---|
| 10 | Скоркард зрелости | Насколько система зрелая? | [maturity-scorecard 7 осей](../../templates/maturity-scorecard-template.md) | балл 7 осей + узкие места и противоречия |
| 11 | 30-дневный тест | Что проверяем первым и по какому порогу? | OPF one-test | одна метрика, порог, что меняем |

**Сквозное:** [банк доказательств метода](../../evidence/one-product-flow-proof-bank.md) · продуктизация (диагностика→спринт→группа→клуб) · гард-рейлы.

> **Конкуренты — не отдельный шаг.** Поверхностно (кто + негатив → барьеры) собираем в шаге 1; глубокое позиционирование и незанятое место — в шаге 6 (оффер), когда ясно, за какой сегмент и с кем деремся. Прогон по шагам-файлам → [steps/](steps/_index.md) (S1…S11).

## 5. Что откуда взято (лучшее из обеих)

| Из Marketing OS (глубина) | Из One Product Flow (фокус) |
|---|---|
| Скрининг: 6-кат. модель параметров → 7-блочная записка → главное ограничение | Проблема-первой: денежная проблема как вход |
| JTBD: 5-7 сегментов, точка слома из негатива, опыт А/Б, приоритизация | **4 силы** (давление текущей ситуации/притяжение результата/тревога перехода/инерция текущего способа) на стартовом сегменте |
| Полный CJM: диалог-цитаты, запросы 15+, места поиска, лид-магниты на шаг | **Уровень Шварца** как явный выбор входа |
| 7 осей зрелости (скоркард) | Дисциплина «один источник / один тест» |
| Модули: оффер, диагностич. продажа, удержание, дожим по контексту | Продуктизация: диагностика→спринт→группа→клуб |
| Гард-рейлы, генеративность, кросс-ссылки | Простой язык клиента (где теряем клиента, незанятое место) |
| Профайл компании, продуктовый юнит, КФВ, 4 уровня ценности | банк доказательств по блокам метода + 90-мин консультация |

## 6. Два scorecard — разведены, оба нужны

Слияние даёт два инструмента оценки. Они **не конкуренты, а разные роли**:

| Scorecard | Роль | Когда | Файл |
|---|---|---|---|
| **OPF Scorecard, 5 блоков (0-30)** | лид-магнит / самодиагностика для клиента на входе | до продажи, руками клиента | [самоскрининг](self-screening-scorecard-2026-07-03.md) |
| **Скоркард зрелости, 7 осей (0-100)** | внутренняя диагностика зрелости системы | шаг 10, аналитиком | [maturity-scorecard](../../templates/maturity-scorecard-template.md) |

5 блоков квалифицируют лида и дают первый инсайт; 7 осей — приборная панель прогресса (пере-замер раз в квартал). Соответствие блоков: Product Focus→оффер/упаковка; Buyer Job→JTBD; Доказательство для клиента→контент/доказательства; Touchpoints→лидген+CJM; Conversion→продажи+удержание+измерение.

## 7. 90-минутная консультация — это «сходимся» в сжатом виде

Полный метод — для спринта. За 90 минут не диагностируем вширь, а **сразу фокусируем**: [consultation-90min-v3](consultation-90min-v3-2026-07-06.md). Порядок консультации = фаза 2 + быстрая версия фаз 1 и 3. Полный скрининг, карта 5-7 сегментов и полный CJM — уже в платном спринте.
