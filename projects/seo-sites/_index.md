# SEO-сайты

**Статус:** research portfolio — приоритет запуска не выбран
**Владелец:** Володя
**Проверено:** 2026-08-20

Папка под SEO-сайты: один подкаталог = один сайт (ниша + гео). Внутри — от разведки ниши до замеров заявок.

Живёт внутри `projects/`, потому что SEO-сайт обслуживает бизнес-проект, но ведётся отдельно от него: у бизнес-проекта свой цикл (продажи, встречи, недели), у сайта — свой (ядро, страницы, позиции, заявки). Связь между ними — строкой «Бизнес-проект» в карточке сайта.

> **Что сюда не относится.** Собственный органический лидген агентства на `volodtarasov.ru` или `ananasm.ru` не смешивается с клиентскими SEO-проектами. Он запускается только после готовности агентского оффера и кейсов → [позиционирование](../ai-infobiz/product/positioning.md), [карточка сайта](../ai-infobiz/product/site-lazyhim.md).
>
> Разница по существу: проекты в этой папке ловят спрос **на услугу клиента** (оклейка, химчистка), личный блог ловит спрос **на решение проблемы владельца** (как привлечь клиентов). Разные аудитории, разные запросы, друг друга не заменяют. **Риск аффилиатности относится только к проектам этой папки** — там, где рядом уже стоит основной сайт того же бизнеса.

## Как устроено

```
projects/seo-sites/
├── _index.md                  ← этот файл: конвенция и статус всех проектов
├── _template/                 ← шаблон нового проекта (копировать, не редактировать)
│   ├── README.md              ← карточка проекта: паспорт, вердикт, статус
│   ├── 01-razvedka/           ← отчёты разведки ниши (скилл razvedka-nishi)
│   ├── 02-semantika/          ← Wordstat: чек-листы фраз, выгрузки, кластеры
│   ├── 03-kontent-plan/       ← очередь страниц, ТЗ на тексты, структура сайта
│   └── 04-zamery/             ← KPI: заявки, трафик по кластерам, позиции по wedge
└── <slug-проекта>/            ← то же самое, заполненное
```

## Как заводить новый проект

1. Скопировать `_template/` в `<ниша>-<гео>/` — слаг строчной латиницей через дефис (`samara-ppf-detailing`).
2. Заполнить `README.md` проекта: паспорт (ниша, гео, модель денег, что уже есть) + ссылку на бизнес-проект в `projects/`, если он есть.
3. Прогнать `/razvedka-nishi` — отчёт кладётся в `01-razvedka/` как `razvedka-<ниша>-<ГГГГ-ММ-ДД>.md`.
4. Из отчёта вытащить список фраз в `02-semantika/wordstat-check.md` и прогнать в Wordstat по региону.
5. Только после реальных частотностей — очередь страниц в `03-kontent-plan/`.
6. Каждый месяц — замер в `04-zamery/`.

Скилл разведки лежит в [.claude/skills/razvedka-nishi/](../../.claude/skills/razvedka-nishi/) — вызывается как `/razvedka-nishi`.

## Правила, общие для всех проектов

Вытащены из `09-quality-onpage.md` скилла — нарушение бьёт по всему сайту, а не по одной странице:

- **Не линковать проекты этой папки между собой dofollow.** Один владелец = аффилированная сетка, Яндекс распознаёт, санкция накрывает всю группу. Нужна ссылка — только `rel="nofollow sponsored"`.
- **Не более 5 новых страниц в день** на один сайт. Программные сетки соблазняют выкатить сотни разом — читается как автогенерация.
- **Никакой накрутки ПФ, никакого автоматического линкбилдинга.** Off-page — вручную, с единым реестром площадок на всю папку (чтобы не купить одну площадку дважды у разных подрядчиков), старт не раньше 2–3 месяцев с появления домена.
- **URL — только строчная латиница** `^[a-z0-9-]+$`, проверять регуляркой, не глазами.
- **Ни одной выдуманной цифры на сайтах**: ни отзывов, ни `AggregateRating` без реальных оценок, ни стажа, которого нет.
- **Ни одной выдуманной цифры в этих документах**: частотности и объёмы — либо из Wordstat/консоли, либо помечены «проверить».

**Приоритет не выбран, и это стало главным вопросом папки.** Пять проектов, ни одного домена. Детейлинг даёт заявки быстрее (топ рыхлый, ядро узкое); трафик — шире и дороже в перспективе; foreign-payments — самый близкий к деньгам и самый дорогой в поддержке; крипта — лучшая экономика на реферала и худшая устойчивость оффера. Вести всё одновременно с нулевыми доменами — гарантированный провал всех. Решение — за владельцем.

## Общая находка: один продукт, три вертикали

`foreign-payments-rf`, `ai-income-rf` и `crypto-trading-rf` независимо пришли к одной и той же продуктовой модели — **датированной проверяемой базе доступности зарубежных сервисов для российского пользователя**:

| Проект | Матрица БД |
|---|---|
| foreign-payments | `карта × сервис × совместимость × полная стоимость × дата теста` |
| ai-income | `ИИ-сервис × доступ из РФ × цена в рублях × чем оплатить × дата проверки` |
| crypto-trading | `биржа × доступ из РФ × KYC × P2P-рубли × комиссии × дата проверки` |

Сущность проверки (`CompatibilityTest` / `AccessCheck`) во всех трёх практически одинаковая, как и wedge: конкуренты публикуют недатированные «ТОП-N», обновлять их атомарно не умеют.

**Следствия:**

- ai-income сливается в foreign-payments силосом `/ai/` — общая аудитория, общий money-слой, общая редакция;
- crypto-trading остаётся **отдельным доменом**: другая аудитория, другой риск-профиль, и крипто-соседство утяжеляет доверие платёжного проекта;
- движок и шаблон теста имеет смысл делать один раз на оба домена.

⚠️ **`ai-income-rf` — кандидат на слияние, а не самостоятельный сайт.** Разведка показала, что его ядро (`нейросети под задачу`) и ядро foreign-payments опираются на одну БД, одну редакцию и один money-слой. Разводить их по двум нулевым доменам — удвоить операционную нагрузку ради того же трафика. Финальное решение — после совместной выгрузки Wordstat.

⚠️ **Проекты этой папки нельзя линковать между собой dofollow.** Соблазн реальный: детейлинг — идеальный кейс для сайта по трафику. Кейс описывать можно, ссылку — только `rel="nofollow sponsored"`.
