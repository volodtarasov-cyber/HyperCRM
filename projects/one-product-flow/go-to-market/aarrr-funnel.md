# One Product Flow — AARRR v0.1

## Входные данные

| Поле | Значение |
|---|---|
| Продукт | One Product Flow — метод сборки пути клиента вокруг одного продукта |
| Первый beachhead | B2B-эксперты и специалисты с дорогой консультационной продажей |
| Главный JTBD | Есть сильный продукт, но заявки идут случайно; нужен понятный путь до заявки/покупки |
| Первый коммерческий шаг | Платный разбор One Product Flow за 20-30к `[Г]` |
| Ограничение | Нет кейсов именно под названием One Product Flow, нет baseline продаж, мало регулярного контента |

## Главный принцип воронки

Не вести холодного человека сразу в спринт или клуб.  
Вести его в **mini-screen одного продукта**, где он увидит, где именно теряет клиента в своём пути.

```text
контент/аутрич
→ mini-screen одного продукта
→ платный разбор
→ спринт / группа
→ клуб / следующий продукт / рекомендация
```

## A — Acquisition

**Цель:** привлечь людей, у которых уже есть дорогой продукт, но заявки идут рывками.

**Каналы:**
- личный Telegram/VK/YouTube;
- тёплый outbound по знакомым и окружению;
- предпринимательские/маркетинговые чаты;
- публичные разборы продуктов;
- later: таргет/ретаргет на метод-пост.

**Углы:**
- "У вас не проблема с контентом. У вас нет собранного пути клиента".
- "Пока продвигаете всё, клиент не понимает, что купить".
- "Реклама не спасёт, если после касания человек не проходит дальше".
- "Контент проще делать, когда он закрывает этапы пути".

**Что является лидом:** человек прислал один продукт/ссылку на профиль/страницу и попросил mini-screen.

**Метрики:**
- просмотры/охваты постов;
- целевые реакции;
- входящие сообщения;
- количество присланных продуктов;
- доля подходящих по anti-ICP.

**Риск:** широкий интерес без покупательной готовности.

## A — Activation

**Цель:** человек впервые почувствовал ценность метода на своём продукте.

**Момент активации:** mini-screen показывает 2-3 конкретных места, где теряем клиента:
- неясный следующий шаг после контента;
- слабая посадка/профиль;
- нет доказательств;
- нет follow-up;
- продукт размыт;
- заявка не квалифицируется.

**Что получает до оплаты:**
- 3 наблюдения по одному продукту;
- один главный риск;
- предложение платного разбора, если проблема реальная.

**Материалы:**
- шаблон mini-screen;
- пример карты One Product Flow;
- пост "что такое One Product Flow";
- список anti-ICP.

**Метрики:**
- mini-screen → запрос на платный разбор;
- mini-screen → созвон;
- качество диалогов;
- повторяющиеся формулировки боли.

**Риск:** бесплатно раздать слишком много и уйти в консультации.

## R — Revenue

**Цель:** превратить интерес в первые оплаты и proof.

**Лестница:**

| Уровень | Продукт | Цена `[Г]` | Цель |
|---|---|---:|---|
| Free | Mini-screen | 0 | активация и квалификация |
| Entry | Разбор One Product Flow | 20-30к | первая оплата, карта потерь |
| Core | Sprint "Сборка вместе" | 90-150к | внедрение первых элементов |
| Premium | Implementation | 250-400к | глубокая сборка с командой |
| Recurring | Клуб / разборы | later | удержание после кейсов |

**Кому что продавать:**
- нет одного продукта → не продавать, сначала сузить;
- есть продукт, но нет цифр → платный разбор;
- есть продукт + цифры + желание внедрять → спринт;
- есть команда/бюджет → implementation;
- маркетологи/спецы → позже группа/клуб.

**Метрики:**
- конверсия mini-screen → оплата;
- средний чек;
- доля апсейла в спринт;
- время от первого касания до оплаты;
- причины отказов.

**Риск:** продать спринт слишком рано и превратиться в ручное агентство.

## R — Retention

**Цель:** сделать разовую диагностику началом системы.

**Поводы вернуться:**
- внедрение 3 приоритетов;
- разбор первых метрик через 30 дней;
- сбор второго продукта;
- обновление контента/доказательств;
- follow-up по незакрытым заявкам;
- ежемесячный разбор в клубе.

**Механика:**
- после диагностики дать 30-дневную карту;
- через 14 дней запросить статус внедрения;
- через 30 дней сделать короткий review;
- предложить спринт/группу/клуб только по фактическому прогрессу.

**Метрики:**
- доля клиентов, внедривших хотя бы 1 приоритет;
- доля пришедших на review;
- апсейл в спринт;
- повторная покупка на второй продукт;
- кейсы/отзывы.

**Риск:** клиент получил ясность, но не внедрил → метод выглядит слабым.

## R — Referral

**Цель:** превращать результат в доверие и новых лидов.

**Когда просить рекомендацию:**
- после mini-screen, если был сильный инсайт;
- после платного разбора, когда клиент получил карту;
- после первых внедрений/заявок;
- после публичного кейса.

**Что дать для рекомендации:**
- короткая формулировка: "Володя разбирает путь клиента вокруг одного продукта";
- один скрин карты без чувствительных данных;
- публичный кейс;
- предложение "пришлите продукт знакомого на mini-screen".

**Метрики:**
- количество рекомендаций;
- входящие по рекомендациям;
- публичные отзывы;
- разрешения на кейс;
- конверсия referral → mini-screen.

**Риск:** просить отзыв до результата, когда есть только "было интересно".

## Тест на 7-14 дней

**Цель теста:** получить первые диалоги и оплаты без запуска рекламы.

**Состав теста:**
1. Опубликовать метод-пост "Что такое One Product Flow".
2. Сделать CTA: "пришлите один продукт на mini-screen".
3. Выбрать 20 тёплых кандидатов из окружения.
4. Каждому отправить персональный mini-screen 3-5 строк.
5. Предложить платный разбор 20-30к тем, у кого боль подтверждена.

**Материалы:**
- метод-пост;
- шаблон mini-screen;
- описание платного разбора;
- пример deliverable;
- таблица учёта диалогов.

**Метрики теста:**
- 20 outbound;
- 10 ответов;
- 5 mini-screen диалогов;
- 2-3 созвона/разбора;
- 1 оплата как минимальный сигнал;
- 3 оплаты как подтверждение гипотезы входного продукта.

**Ответственный:** Володя.  
**Исполнители:** без команды на первом тесте; команда подключается только после proof.

## Что не делать в тесте

- не запускать рекламу;
- не делать большой лендинг;
- не открывать клуб;
- не обещать x2-3;
- не брать клиентов без одного продукта;
- не добавлять дальние задачи в vault.
