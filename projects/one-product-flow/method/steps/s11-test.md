# S11 · 30-дневный тест

> **Фаза 4 · Тест.** Цель: одна проверяемая гипотеза на 30 дней. Это финал воронки — проверяем собранный поток в бою. **Успех = взяли метрику ИЛИ получили точный диагноз, где поток сломался и какой рычаг менять. Тест обязан учить в любом случае.**

**Вход:** все шаги (собранная воронка).

## 0. Замер ДО и атрибуция (до запуска — иначе результат недоказуем)

- **Baseline:** зафиксировать текущие цифры по продукту ДО теста — заявок/мес, CPL, конверсия заявка→оплата, средний чек, выручка. Нет цифры → `[нет данных]`, тогда результат покажем в абсолюте, не в приросте.
- **Атрибуция:** UTM на все ссылки · колл-трекинг на звонки · промокод для офлайна/мессенджеров · один источник истины (CRM). Без этого «результат» не привязать к тесту.
- **Правило:** не запускаем тест, пока не понятно, с чем сравниваем и как померим.

## 1. Минимальная цепочка воронки

```text
касания → переходы → заявки → квалифицированные → созвоны/расчёты → оплаты → выручка
```

## 2. Что фиксировать по этапам

- **источник** (S7): касания → переходы;
- **точка входа** (S6/S8): конверсия перехода в заявку;
- **заявка** (S9): качество/сегмент;
- **продажа** (S9): созвоны → оплаты;
- **дожим** (S9): вернувшиеся тёплые.

## 3. Дизайн теста

- **Одна главная метрика** (та, что бьёт по текущему ограничению из S1).
- **Порог успеха** — число, ниже которого гипотеза не подтвердилась.
- **Что меняем, если не сработало:** сменить уровень (S4) / оффер (S6) / источник (S7) / сегмент (S3) — по одному за раз.

## 4. Ведущие индикаторы — тест всегда учит

Читаем воронку по этапам на день **7 / 14 / 30**, не ждём финала:
```text
показы → CTR → клик → лид (CPL) → квал → созвон → оплата (CPO)
```
- На каждом этапе — план vs факт. **Где просело относительно нормы — там и сломалось.**
- Просело вверху (CTR/CPL) → канал / угол / уровень (S4, S7).
- Просело в середине (лид→квал/созвон) → оффер / сегмент (S3, S6).
- Просело внизу (созвон→оплата) → продажа / дожим / цена (S6, S9).

Так даже «неудачный» тест даёт **точный диагноз и следующий рычаг** — это и есть почти гарантированный результат.

## Рекомендация этапа — готовность к запуску (не обязательно)

Мягкий чек-лист перед стартом (не гейт):
- креативы/тексты готовы под угол уровня (S4/S7);
- посадка работает и ведёт к целевому действию;
- proof на точках перелома на месте (S8);
- трекинг живой (UTM / колл-трекинг / промокод пишутся в CRM);
- бюджет выделен, хватает на статзначимый сигнал;
- назначен ответственный за заявки + SLA ответа (S9).

## Критерий готовности — перейти к сборке (итог) только после подтверждения

- [ ] Зафиксирован baseline (или помечено `[нет данных]`) и настроена атрибуция.
- [ ] Определены ведущие индикаторы по этапам и нормы (план vs факт) для чтения на 7/14/30.
- [ ] Определены метрика, порог и план изменения.
