# One Product Flow — Метод

> Сам метод, по которому веду людей на диагностике и в спринте. Как продаю и продвигаю OPF → [../go-to-market/](../go-to-market/_index.md). Общая карта проекта → [../_index.md](../_index.md).

**Спайн:** [method-canonical-v3](method-canonical-v3-2026-07-06.md) — канонический метод, объединяющий глубину Agency OS и фокус OPF.

Цепочка: `проблема → работа (JTBD) → сегмент → beachhead (1 сегмент) → 4 силы → уровень Шварца → продукт → оффер → источник → CJM → дожим → метрики`.

> **Порядок работа→сегмент, не наоборот.** Работа (JTBD) — ось сегментации (S2): 5-7 работ порождают 5-7 сегментов, сегмент = носитель работы. Сегмент выбираем внутри карты работ (beachhead, S3), и только потом разбираем 4 силы по нему.

**Обзор для рассказа за 2 секунды:** [method-mindmap](method-mindmap-2026-07-06.md) — майнд-карта всех этапов «что делаем → что получаем».

**Полный процесс (прогон сверху вниз, все вопросы инлайн):** [full-process](full-process-2026-07-06.md) — весь путь вплоть до 58 вопросов скрининга, самодостаточно.

**Прогон по шагам S1…S11 (шаг за шагом, с подтверждением):** [steps/](steps/_index.md) — каждый шаг даёт артефакт в [сборку](steps/_assembly-template.md). Двигаемся дальше только после подтверждения предыдущего. S1 = компания/эксперт + текущая ситуация (слиты вход и скрининг); отдельного шага «конкуренты» нет — позиционирование в S6 (оффер).
