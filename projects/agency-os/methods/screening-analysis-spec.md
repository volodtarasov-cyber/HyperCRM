# Генеративный спек скрининга (реверс-инжиниринг Ребдеу)

> **Что это:** не шаблон вывода, а **инструкции, которые порождают вывод** — как думает аналитик-скрининг. Восстановлено из полного разбора скрининга Ребдеу (4 вкладки: Диагностика, План, Зоны внимания, Приоритет, Сегмент + JTBD/CJM-дампы).
> **Зачем:** чтобы скиллы кодировали методологию (богатство + рассуждение), а не форму ответа. Источник правды для скилла `/screening` и цепочки.
> ⚠️ **Скоуп: на ПРОДУКТ/ЮНИТ, не на компанию.** У каждого продукта (плёнка, шумка, полировка…) — своя цепочка скрининг→сегмент→план. Компания = общий контекст сверху.

---

## 1. Модель параметров (ядро)

Скрининг строит **нумерованную модель параметров** по категориям. Каждый параметр имеет ID и значение/оценку. **Любой вывод цитирует параметры по ID** как доказательство — не «у вас слабые продажи», а «низкая конверсия (параметр 5.2)».

Категории (под детейлинг, адаптировать под нишу):
```
1. Рынок и спрос      (1.8 частота потребности, 1.15 восприятие покупки …)
2. Продукт и компания (гарантия, возвраты, опыт мастеров, персоналозависимость)
3. Маркетинг/упаковка  (3.3 КА проведён, 3.4 смысловая упаковка, 3.6 форматы, 3.8 анти-ЦА)
4. Реклама            (4.3 посылы, 4.4 уровни теплоты, 4.8 число источников)
5. Продажи            (5.2 конверсия, 5.5 глубина чека, 5.10 РОП, 5.11 мотивация, 5.14 концентрация выручки, 5.15 цикл сделки, 5.16 маркетолог с правом решения)
6. Аналитика          (6.4 аналитик есть)
```
→ При прогоне нумеровать параметры под конкретную нишу/продукт; держать их как «доказательную базу», на которую ссылаются все выводы.

## 2. Вывод = аналитическая записка из 7 вкладок

### Диагностика
Оценка по разделам (см. наш [скоркард зрелости](../templates/maturity-scorecard-template.md)) + общий балл.

### Выводы
Синтез: главные противоречия и узкие места (пары «X есть vs Y теряется»).

### Рынок
Характеристики спроса по продукту: тип ниши (мягкая/жёсткая), эластичность, цикл решения, сезонность, поисковый спрос с объёмами.

### Сегмент (ключевой)
Портрет главного сегмента продукта:
- **формулировка от лица клиента** (в кавычках, его словами);
- **почему именно этот сегмент** (массовость · рациональность/эмоция · готовность к чеку · соответствие продукту);
- портрет (кто, возраст, ситуация), задача, **триггеры покупки**, **страхи**, **что отталкивает**, **Core Job**, **критерии к компании**.

### План (тактики, приоритизированные)
На каждую тактику:
- название + **почему она в этой очереди** (зависимость от других: «без аналитики нельзя измерить улучшение»);
- **этапы пути клиента**, которые трогает (связь с CJM);
- **срок** (X недель);
- **`[T##]` обоснование** — со ссылками на параметры по ID;
- **подшаги** — каждый: жирное действие + конкретика;
- **Артефакт** (что на выходе);
- **Метрика** — числовая («+5–10 п.п. конверсии», «CPL −20–35%»);
- **Риск** — конкретный режим провала + что делать;
- **Реалистичность** — обоснование на данных профиля + дисклеймер «ориентир, не прогноз, затраты не оцениваются».

### Зоны внимания
- **Гипотезы на проверку (Г1…)**: утверждение → ветки **«Если X»** с рассуждением → **Действие** (как проверить в CRM/1С).
- **Чего НЕ делать (анти-паттерны)**: **Логика ошибки** (заманчивое «давайте…») → **Реальность** (почему неверно, с цифрами) → **Правильно** (верная последовательность).

### Приоритет
**3 действия на этой неделе**: без бюджета, без согласований, дают первые данные за 2–3 недели. Запускаются параллельно.

## 3. Движок рассуждения (то, что отличает глубину от шаблона)

1. **Всё цитирует параметры по ID.** Нет «голых» утверждений.
2. **Считай экономику и проверяй на сходимость.** Пример (Г1): «300 лидов × CPL 1 800 = 540к, а бюджет заявлен 100–200к — не сходится → уточнить структуру лидов и реальный CPL по каналам». Числа должны биться между собой.
3. **Бросай вызов вводным.** Не принимай профиль на веру — строй гипотезы «если X, то Y» и давай способ проверки.
4. **Каждая тактика измерима и заземлена:** артефакт + числовая метрика + риск + реализм на профиле.
5. **Приоритет: сначала измерение и конверсия, потом трафик.** Анти-паттерн №1 — лить бюджет при низкой конверсии (математика: поднять конверсию 5%→12% даёт +21 сделку без бюджета).
6. **Связывай тактики между собой и с путём.** «Видеокейсы (Т5) дают контент для ВКонтакте (Т7)»; каждая тактика привязана к этапам CJM.
7. **Барьеры/страхи — из реальности, не из головы:** негатив конкурентов + точки слома CJM + отзывы.
8. **Реализм честный:** оценки — ориентир на самозаявленных данных, не прогноз; затраты на внедрение не оцениваем; помечать `?`.

## 4. Связь с цепочкой
Скрининг (этот спек) → даёт параметры и узкие места → [JTBD-сегменты](../modules/niche-icp-jtbd-research.md) (глубже сегмент) → [CJM](../modules/customer-journey-map.md) (путь, точки перелома, лид-магниты, каналы) → оффер/продажи/удержание. Всё — **на один продукт за прогон**.

> Аналогичные генеративные спеки нужны для JTBD и CJM (дампы полного вывода Ребдеу есть) — следующий слой сборки системы.
