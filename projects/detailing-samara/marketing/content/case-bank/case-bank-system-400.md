# Система сбора контента и кейс-банк на 400 работ

## 0. Зачем

Через 3-5 лет у Левши должна быть база минимум **400 подробных кейсов** по реальным работам: плёнка, мойка, полировка, химчистка, PDR, тонировка, шумка, стекла, комплексные проекты.

Это не задача SMM "пофоткать". Это отдельная операционная система:

```text
каждый подходящий заказ
→ фиксируется до/в процессе/после
→ получает фактуру
→ складывается в базу
→ превращается в кейс, карточку услуги, пост, Авито-пример, SEO-страницу
```

Без системы кейсы теряются в телефонах, чатах и памяти мастеров. С системой каждый сильный заказ становится активом продаж на годы.

## 1. Цель в цифрах

Минимальная цель: **400 подробных кейсов за 3-5 лет**.

| Горизонт | Нужно кейсов в год | Нужно кейсов в месяц |
|---|---:|---:|
| 3 года | 133 | 11-12 |
| 4 года | 100 | 8-9 |
| 5 лет | 80 | 6-7 |

Рабочая норма: **8-12 кейсов в месяц**.

Стартовый KPI на первые 90 дней:

| Метрика | Цель |
|---|---:|
| Заказов с фотофиксацией до/после | 30+/мес |
| Кандидатов в кейсы | 15+/мес |
| Подробных кейсов в базу | 8+/мес |
| Кейсов, опубликованных хотя бы в 1 канал | 6+/мес |

## 2. Что считается подробным кейсом

Кейс засчитывается в базу, если есть минимум:

- дата и услуга;
- марка/модель авто;
- задача клиента;
- что было до работы;
- что сделали по зонам;
- материал / технология / гарантия, если применимо;
- срок работы;
- результат;
- рекомендации по уходу;
- 5+ фото: до, процесс, после, крупные детали;
- разрешение на публикацию или отметка "без номера / без лица".

Полная структура кейса уже зафиксирована в [case-structure-template.md](case-structure-template.md).

## 3. Уровни кейсов

Не каждый заказ нужно превращать в длинную статью. Нужны три уровня:

| Уровень | Что это | Где использовать |
|---|---|---|
| **A — полный кейс** | Страница/лонгрид с задачей, процессом, фото, результатом | сайт, SEO, презентации, Авито, соцсети |
| **B — мини-кейс** | 1 экран: авто, задача, что сделали, 3-5 фото | карты, Авито, соцсети, карточки услуг |
| **C — сырьё** | фото/видео + короткая фактура без упаковки | архив, будущие подборки, рекламу |

В цель **400 кейсов** засчитываются A и B, если заполнены обязательные поля.

## 4. Какие работы собирать в первую очередь

Приоритет 1:

- плёнка 100к+;
- полная / передняя оклейка;
- премиальные и популярные модели;
- комплексные работы: плёнка + полировка + керамика / химчистка;
- кейсы с понятным "до/после".

Приоритет 2:

- локальные доклейки после большой плёнки;
- полировка и защитные покрытия;
- химчистка с сильным визуальным результатом;
- PDR до/после;
- тонировка / бронь стёкол;
- шумка с разбором салона.

Приоритет 3:

- мойка, если есть премиум-авто, сильный визуал или диагностическая история;
- сезонные работы;
- необычные задачи.

## 5. Процесс на каждый подходящий заказ

### 5.1. Приёмка

При захвате (Вика) фиксируем:

- марка/модель/год;
- задача клиента;
- услуга / пакет;
- почему клиент приехал;
- можно ли снимать и публиковать без номера;
- есть ли ограничения: не показывать лицо, номер, салон, цену.

### 5.2. До работы

Нужно снять:

- общий вид авто;
- зоны риска / дефекты;
- крупные планы: капот, бампер, фары, пороги, салон;
- фото под углом и под светом, если это полировка/PDR.

### 5.3. Процесс

Нужно снять:

- подготовку;
- руки мастера в работе;
- раскладку плёнки / машинку / экстрактор / инструмент PDR;
- сложные зоны;
- контроль качества.

### 5.4. После

Нужно снять:

- общий вид авто;
- те же зоны, что были "до";
- крупные детали результата;
- выдачу / паспорт защиты / рекомендации.

### 5.5. Упаковка

Помощница/SMM собирает карточку кейса:

- заголовок;
- короткий итог;
- фактура;
- фото;
- каналы публикации;
- статус: сырьё / мини-кейс / полный кейс / опубликовано.

> ⚠️ Актуальные роли — в [case-production-system.md](case-production-system.md) (**двое: Володя + Вика, мастера не участвуют**). Таблица ниже — старая рамка 01.06, оставлена как референс.

| Роль | Ответственность |

| **Володя** | раз в неделю — качество кейсов и приоритеты для маркетинга/SEO |
| Александр | по запросу — техническая фактура, спорные формулировки (не ведёт систему) |

## 8. Таблица кейс-банка

Минимальные поля:

| Поле | Зачем |
|---|---|
| ID кейса | связь с папкой |
| Дата | сортировка |
| Заказ-наряд | связь с 1С/Б24 |
| Клиент / приватность | не публиковать лишнее |
| Марка/модель/год | SEO и подборки |
| Услуги | фильтры |
| Чек / диапазон | управленческая аналитика, можно не публиковать |
| Задача клиента | сюжет |
| Что сделали | тело кейса |
| Материал / гарантия | доверие |
| Фото до | контроль полноты |
| Фото процесс | контроль полноты |
| Фото после | контроль полноты |
| Статус | сырьё / B / A / опубликовано |
| Каналы | сайт / карты / Авито / VK / Директ |
| Ответственный | кто доводит |

## 9. Еженедельный ритм

Каждый понедельник:

1. Посмотреть заказы прошлой недели.
2. Выбрать 3-5 лучших кандидатов.
3. Проверить, хватает ли фото и фактуры.
4. Назначить, что идёт в полный кейс, что в мини-кейс.
5. Опубликовать минимум 1-2 кейса.
6. Догрузить 3-5 фото в карты.

Каждый месяц:

1. Закрыть 8+ кейсов в базу.
2. Сделать 1 подборку: "5 примеров плёнки на SUV", "до/после химчистки", "PDR без покраски".
3. Обновить Авито и карточки услуг свежими примерами.
4. Передать лучшие кейсы в SEO-план сайта.

## 10. Первые 30 дней

1. Создать таблицу кейс-банка.
2. Создать структуру папок.
3. Назначить ответственных.
4. Ввести чек-лист фото на приёмке/выдаче.
5. Выбрать 20 старых работ из телефонов/архива и довести хотя бы 8 до мини-кейсов.
6. Снять 5 новых работ по полному процессу.
7. Опубликовать первые 3 кейса: плёнка, полировка, химчистка.

## 11. Риск

Главный риск: сделать красивый шаблон, но не встроить сбор в операционку.

Поэтому первый критерий успеха не "идеальные посты", а наличие ежедневного сырья:

```text
есть заказ → есть фото до/после → есть фактура → есть папка → есть статус в таблице
```

Публикация идёт вторым слоем.
