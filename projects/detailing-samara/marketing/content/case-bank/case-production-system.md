# Кейс-производство — система на одной Google-таблице

> **Что это:** рабочая система, которая превращает заказ в кейс. Один инструмент — **Google Sheets** (и она же реестр, и она же конвейер). Слой workflow поверх [case-bank-system-400.md](case-bank-system-400.md) (зачем/цель/банк) и [case-photo-video-structure.md](case-photo-video-structure.md) (что снимать).
> **Кто делает:** Володя + Вика (SMM) — вдвоём. Мастера в системе **не участвуют**.
> **Почему не YouGile:** на 8-12 кейсов/мес и двух исполнителей второй инструмент = двойной ввод = система умирает. Таблица делает и хранение, и отслеживание. YouGile вернём только если кейсы начнут теряться из-за «непонятно чья задача» — сейчас задача всегда Викина.
> **Критерий, что система жива:** есть ежедневное сырьё (фото до/после в папке + строка в таблице). Публикация — второй слой.

---

## 1. Инструменты (минимум)

| Слой | Инструмент | Что держит |
|---|---|---|
| **Реестр + конвейер** | **Google Sheets** — «Кейс-банк Левша» | все кейсы, статус, что снято, где опубликовано |
| **Файлы** | **Google Drive / Я.Диск** | папки кейса (фото/видео) |

Всё. Таблица одновременно и банк (актив на 400 кейсов), и трекер «что в работе / что зависло».

---

## 2. Как кейс попадает в систему (захват)

Триггер — не пуш в приложении, а **реальная машина на выдаче**. **Вика** ведёт захват сама: увидела сильную работу (на приёмке/выдаче или по графику смен) → завела строку в таблице → сняла по чек-листу.

> Захват целиком на Вике. Не плодим лишних участников — на 8-12 кейсов/мес это перегруз.

---

## 3. Структура таблицы «Кейс-банк Левша»

**Лист 1 — `Банк` (главный, одна строка = одна машина):**

| Столбец | Тип | Зачем |
|---|---|---|
| ID | авто/текст | `2026-06-05_haval-jolion_zn-1234` — связь с папкой |
| Дата | дата | сортировка |
| ЗН (заказ-наряд) | текст | связь с 1С/Б24 |
| Марка / Модель / Год | текст | SEO, подборки, фильтр |
| Услуга | dropdown | плёнка · шумка · полировка · химчистка · PDR · тонировка · комплекс |
| Приоритет | dropdown | 🟥 П1 (плёнка 100к+, премиум, явное до/после) · 🟧 П2 · ⬜ П3 |
| Согласие | dropdown | ✅ полное · ⚠️ ограничения · ⛔ нельзя |
| **Статус** | dropdown | 🆕 Кандидат · 🎥 Снимаем · 🗂 Упаковка · 📢 Опубликован · 🗑 Отказ |
| ДО | чекбокс | контроль полноты |
| Процесс | чекбокс | контроль полноты |
| ПОСЛЕ | чекбокс | контроль полноты |
| Уровень | dropdown | A (полный) · B (мини) · C (сырьё) |
| Папка | ссылка | на Drive |
| Каналы | текст/чекбоксы | сайт · пост · Авито · reels — где вышло |
| Чек (внутр.) | число | аналитика, **не для публикации** |
| Ответственный | dropdown | Вика · Володя |
| Заметка | текст | нюанс, сюжет, что добить |

**Лист 2 — `Сводка`** (формулы, ничего не вводим руками):
- Кейсов в банке (A+B опубликованных) — счётчик к цели 400
- За этот месяц: кандидатов / снято / упаковано / опубликовано (норма 8-12)
- 🔴 **Зависшие** — список строк, где статус «Снимаем», ПОСЛЕ пустой, а дата старше 3 дней

**Лист 3 — `Идеи подборок`** — «5 плёнок на SUV», «до/после химчистки» и т.п.

---

## 4. Светофор (условное форматирование — конвейер без канбана)

Это заменяет колонки YouGile. Настроить на листе `Банк`:

- Статус `🆕 Кандидат` старше **2 дней** → строка 🟡 (не сняли — догнать).
- Статус `🎥 Снимаем` + ПОСЛЕ пустой + дата старше **3 дней** → строка 🔴 (потеряем материал).
- Статус `🗂 Упаковка` старше **7 дней** → строка 🟧 (висит без публикации).
- Статус `📢 Опубликован` → строка 🟢 (готово, в банке).

Раз в неделю Вика смотрит только на красное/жёлтое — это и есть весь контроль.

---

## 5. Маршрут одной строки (DoD на каждый статус)

| Статус | Что должно быть, чтобы перевести дальше |
|---|---|
| 🆕 Кандидат | согласие отмечено, марка/задача записаны, папка заведена |
| 🎥 Снимаем | закрыты чекбоксы ДО / Процесс / ПОСЛЕ (по [структуре съёмки](case-photo-video-structure.md)) |
| 🗂 Упаковка | поля кейса заполнены ([шаблон](case-structure-template.md)), фото отобраны в `04_selected`, проставлен уровень A/B |
| 📢 Опубликован | вышло минимум в **2 канала** из 4, отмечено в «Каналы» |

> **Money shots, без которых кейс слабый** (из [структуры съёмки](case-photo-video-structure.md)): до/после на идентичном ракурсе · макро аккуратности (подворот/шов) · hero машины в боксе. Сняли только эти три — кейс уже живой.

## 7. Роли (двое)

| Кто | Что делает |
|---|---|
| **Вика (SMM)** | захват, заводит строку, снимает ДО/процесс/после, упаковывает, публикует, ведёт таблицу и светофор |
| **Володя** | раз в неделю — качество и приоритеты под маркетинг/SEO; снимает сам, если Вики нет на сильной работе |

Мастера в системе не участвуют.

---

## 8. Ритм

- **Каждую неделю (Вика):** глянуть красное/жёлтое в светофоре, добить 3-5 кандидатов, опубликовать 1-2, догрузить фото в карты.
- **Каждый месяц:** закрыть 8+ кейсов в банк (норма к цели 400 за 3-5 лет), собрать 1 подборку, обновить Авито/карточки свежими примерами, лучшее → в SEO-план.
- **Володя:** раз в неделю 15 минут — смотрит качество и расставляет приоритеты.

---

## 9. Старт — первая неделя

1. Создать таблицу `Кейс-банк Левша`: лист `Банк` со столбцами (разд. 3), dropdown-списки, чекбоксы.
2. Настроить светофор (разд. 4) и лист `Сводка` со счётчиками.
3. Создать структуру папок на Drive, одну папку-эталон.
4. **Цель недели: 3 кейса с телефона** — плёнка / полировка / универсал — до статуса 📢 Опубликован. Это топливо для воронки прогрева (HYP-010).

---

## 10. Почему не сломается

Главный риск — красивая система без встройки в операционку. Защита здесь:
- **один инструмент** (нет двойного ввода),
- **один исполнитель** (всё на Вике, не размазано по мастерам),
- **один захват** (чат для флагов + Вика на выдаче),
- **светофор** сам подсвечивает зависшее — не надо помнить.

```
машина на выдаче → строка в таблице → фото в папке → статус → светофор не даёт забыть
```
