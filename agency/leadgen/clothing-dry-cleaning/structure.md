# Как пополнять и измерять направление

Это рабочая структура направления, а не новая маркетинговая методология. Определения → [словарь Marketing OS](../../../marketing-os/core/glossary.md), метод исследования → [ICP + JTBD](../../../marketing-os/engines/niche-icp-jtbd-research.md).

## Структура

```text
clothing-dry-cleaning/
  _index.md                        вход в направление
  structure.md                     правила пополнения и связи
  research/                        общая разведка и происхождение данных
    _index.md
    sources.md                     реестр внешних и собственных источников
    observations/_index.md         указатель конкретных наблюдений
  jtbd/<работа>/
    _index.md                      работа и её границы
    segments/<сегмент>/
      _index.md                    ситуация выбора и границы сегмента
      audience/                    знания о покупателях этого сегмента
      funnels/
        _index.md                  список воронок сегмента
        <воронка>/
          _index.md                паспорт и версия связки
          acquisition.md           привлечение
          activation.md            первая польза
          revenue.md               покупка
          retention.md             продолжение работы
          referral.md              рекомендации
          measurement-and-test.md  события и показатели конкретной связки
          ...                      сценарии и материалы этой воронки
    offer.md                       общая логика предложения под работу
    money-model.md                 экономика
    validation.md                  исследовательские вопросы и протокол
  measurement/                     общий учёт измерений направления
    _index.md
    data-contract.md               поля и правила сопоставимости
    experiments.md                 ссылки на фактически начатые проверки
    results/                       выводы реальных проверок, когда они появятся
  templates/                       формы новых наблюдений, сегментов и проверок
```

Папка `results/` создаётся при первом реальном результате. Материалы одной воронки не размножаются при добавлении нового возражения. Новая воронка нужна, когда меняется связка входа, первой пользы или пути; новая версия материала в прежнем пути остаётся внутри этой воронки.

## Кто чем владеет

| Сведения | Каноническое место |
|---|---|
| Источник, дата, рынок, ограничения | [research/sources.md](research/sources.md) |
| Конкретное наблюдение и контекст | Исходная карточка клиента / документ источника; [указатель](research/observations/_index.md) связывает их с анализом |
| Что мы поняли об аудитории | `audience/` конкретного сегмента; каждый вывод ссылается на наблюдения |
| Граница работы и сегмента | Соответствующие `_index.md` |
| Сообщение, материал, этап и результат первой пользы | Файлы конкретной воронки |
| Определение показателя | `measurement-and-test.md` воронки; общие поля — [единый контракт](measurement/data-contract.md) |
| Наблюдавшийся результат проверки | Отдельный документ `measurement/results/<ID>.md`, ссылка из реестра |
| Новое коммерческое предположение | [Гипотезы агентства](../../hypotheses.md); здесь ссылка, а не второй реестр |
| Цена, исполнитель и себестоимость действующего клиента | [Реестр клиентов](../../../clients/_index.md) |
| Задачи, сроки, поручения | YouGile; не эта база |

Ссылки на вывод допустимы во многих материалах; сам факт и его актуальная формулировка имеют одного владельца. Исходную историю клиента не копируем в каждый сценарий.

## Постоянные ID

| Объект | Принцип | Уже назначено |
|---|---|---|
| Направление | Короткий постоянный код | `CDC` |
| Работа | Код направления + J + номер | `CDC-J01` |
| Сегмент | Код направления + S + номер | `CDC-S01`, `CDC-S02` |
| Воронка | Код направления + F + номер | `CDC-F01` |
| Источник | Существующий код реестра | Группы и занятые номера [реестра](research/sources.md) |
| Наблюдение | Номер в указателе наблюдений | `CDC-OBS001` и далее |
| Вывод об аудитории | Сегмент + I + номер | `CDC-S01-I01` и далее |
| Реальное возражение | Сегмент + OBJ + номер | Первый ID выдаётся при появлении основания |
| Материал | Воронка + локальный код + версия | Например, `CDC-F01-C01-v1`; это обозначение подготовленной версии, не публикации |
| Проверка | Направление + EXP + номер | Первый ID выдаётся при фактическом начале наблюдения |

ID не меняется при переименовании файла или заголовка и не выдаётся заново после удаления. Номера новых объектов — следующие свободные в соответствующем реестре. Переименование смысла наблюдения требует нового ID; исправление источника сохраняет ID с объяснением коррекции.

## Как добавлять информацию

1. Найти существующий источник и эпизод. Повтор одного рассказа или отзыв на другой площадке не становится новым покупателем.
2. Для нового источника добавить карточку в `sources.md`. Разделить дату события, публикации и получения сведений; неизвестную дату не восстанавливать.
3. Выделить конкретное наблюдение, указать источник, точное место и единицу анализа. Добавить ID в [указатель наблюдений](research/observations/_index.md); для нового материала использовать [форму](templates/observation.md).
4. Связать наблюдение с существующим выводом аудитории либо создать новый. Отдельно отметить поддержку и противоречия. Пересказ, прямой ответ и аналитический вывод различаются.
5. Указать применение: конкретный этап воронки, оффер или вопрос исследования. Не превращать каждую найденную боль в новый продукт.
6. Когда проводится проверка, заранее зафиксировать версию материала, объект, период и показатели. После неё сохранить наблюдавшийся результат с ограничениями и связанными ID.

## Различаем знание и исполнение

- Сообщено владельцем агентства — источник о практике или пересказ опыта; не прямое интервью покупателя.
- Прямой материал покупателя — его слова в указанном контексте; не обязательно общая закономерность.
- Аналитический вывод — наша интерпретация с основаниями и границами.
- Гипотеза — предполагаемая связь для проверки; не измеренный эффект.
- Неизвестно — отсутствие данных. Оно не заменяется правдоподобной болью или возражением.

Новые подтверждения и опровержения добавляются к выводу. Отвергнутую формулировку не оставляем активной: корректируем вывод, объясняем, что именно его изменило, сохраняем ссылку на основание. Число строк не равно числу независимых компаний.

## Что измеряем раздельно

**Исследование:** какие поля выбора заполнены, сколько независимых эпизодов даёт основание конкретному выводу, есть ли противоречия, какие рынки и типы компаний представлены. Это глубина знания, не конверсия.

**Воронка:** уникальные компании и фактические события по определению показателей, период и незавершённые пути. Это поведение, не согласие с концепцией.

**Исполнение и экономика:** часы, денежные расходы и их полнота, реальная поставка, платежи и продолжение работы. Стоимость и загрузка Володи — по [финмодели](../../finmodel.md), без новой вменённой ставки.

Структура позволяет добавлять новые воронки в сегмент, сегменты в работу и работы в нишу. Отдельные папки для каждого страха или каждого слова не нужны: новая карточка выделяется, когда появляется самостоятельный эпизод или значительный объём материалов.
