# Create Master Notes

Turn a source into a reliable working document, not a shortened retelling. Preserve the author's reasoning and useful specifics while separating source claims from analysis and adaptation.

## Workflow

### 1. Establish the task

Identify:

- source type, language, author, and apparent purpose;
- intended reader and desired depth;
- whether the user needs only notes or also implementation, critique, or original content;
- relevant business or project context available in the workspace.

Do not delay for clarification when the source and requested outcome make a reasonable default possible. Default to a detailed Markdown artifact for long material.

### 2. Inspect the complete source

Read the whole source before drafting. For long files, read sequential chunks and keep a section inventory.

Remove interface noise, recommendations, duplicated captions, and transcription artifacts from the semantic analysis. Silently correct obvious transcription errors only when the intended meaning is clear. Mark unclear passages instead of inventing meaning.

### 3. Build an argument map

Before writing prose, identify:

- the central promise or question;
- the main thesis;
- the sequence of supporting arguments;
- mechanisms explaining why each claim should be true;
- examples, cases, analogies, formulas, frameworks, and numbers;
- caveats, prerequisites, exceptions, and contradictions;
- calls to action and promotional segments.

Keep causal links explicit: problem -> cause -> proposed mechanism -> action -> expected result.

### 4. Classify evidence

Use these labels when they improve clarity:

- **Source claim**: stated by the author but not independently verified.
- **Source example**: anecdote or case presented by the author.
- **Derived insight**: conclusion logically inferred from several source passages.
- **Adaptation**: recommendation tailored to the user's situation.
- **Open question**: missing information needed before implementation.

Never convert a marketing claim into a fact. Preserve exact numbers that matter, but attach them to their source and context. If current external verification is required, browse authoritative sources and cite them; otherwise state that verification was outside scope.

### 5. Write the master note

Unless the user requests another structure, produce:

1. Source card
2. Executive summary
3. Thesis in one sentence
4. Argument map
5. Detailed section-by-section notes
6. Frameworks, formulas, and checklists
7. Examples and proof used by the author
8. Assumptions, weak points, and unverified claims
9. Practical implementation plan
10. Adaptation to the user's context
11. Questions to resolve
12. Compact reference sheet

Retain meaningful repetition only when it has a rhetorical function. Prefer precise paraphrase over long quotation.

### 6. Create original content from the source

When the user wants their own video, article, lesson, or presentation:

- extract transferable principles, not the source's wording;
- combine those principles with the user's data, cases, point of view, and audience;
- choose a distinct thesis, structure, examples, and title;
- identify where original proof or filming material is required;
- distinguish `inspired by` from `copied from`;
- avoid reproducing the source's distinctive sequence, hooks, phrases, or branded framework names unless attribution is intended.

For video foundations, include:

- audience and job-to-be-done;
- one core promise;
- differentiated angle;
- narrative spine;
- chapter sequence;
- hook options;
- proof and visual requirements;
- CTA;
- claims that require verification;
- production checklist.

### 7. Run quality control

Read [references/quality-rubric.md](references/quality-rubric.md) and audit the draft before delivery.

Confirm that:

- every major source section is represented;
- the note preserves mechanisms, examples, and caveats;
- promotional content is identified rather than absorbed as instruction;
- source claims and adaptations are visibly distinct;
- the output is useful without reopening the source;
- the proposed original content has a genuinely different angle.

## Writing Standard

Write in the user's language unless asked otherwise. Use clear headings, short paragraphs, tables only when comparison benefits from them, and flat lists.

Optimize for information density, traceability, and actionability. Do not pad the note with generic lessons that the source did not support.

For long work, save artifacts in the relevant project folder with descriptive dated filenames. Link the final files.
