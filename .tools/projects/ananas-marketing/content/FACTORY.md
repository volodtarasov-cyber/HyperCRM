# Контент-завод агентства

Локальная панель для очереди материалов, просмотра комплектов, календаря Instagram / Threads / Telegram и учёта результатов. Основной адрес: **http://127.0.0.1:8766/**.

## Запуск

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .tools/projects/ananas-marketing/content/open-content-factory.ps1
```

Для ручного входа браузер должен быть видим на обычном рабочем столе Windows. При запуске помощником из изолированной среды запускать этот файл вне неё. Профиль Chromium и VPN используются те же, что у публикатора. Если завод уже работает, команда открывает панель. Прежний интерфейс доступен по `/publisher`.

После закрытия окна браузера сервер и проверка очереди останавливаются. Для выпуска по времени нужны включённый компьютер, доступная интерактивная сессия Windows, работающий VPN и действующий вход. Установка автозапуска Windows не производится этой командой.

## Работа в панели

1. **Очередь.** Добавить Markdown-источник либо импортировать подготовленную папку из `.tools/carousel-out/`. У материала три выпуска с независимыми состояниями.
2. **Подготовка.** В карточке доступен бриф для помощника. Он использует `/agency-carousel`, готовит тексты трёх площадок, карточки и превью сетки. Готовый комплект импортируется по ID исходного материала. Фоновый вызов ИИ не подключён.
3. **Просмотр.** Проверить факты, раскрытие данных, подписи и обложку. Сохранить выбранный аккаунт и текст, затем одобрить конкретную версию. Изменение текста или аккаунта снимает одобрение. Изменение PNG требует повторного импорта и одобрения.
4. **Выпуск.** Для Instagram и Threads подготовить черновик в браузере, проверить его и нажать «Опубликовать». Либо выбрать время, включить автоматический выпуск этой записи и общий режим в разделе «Состояние». Telegram @lazyhim пока выпускается вручную: текст копируется из карточки, после размещения сохраняется ссылка.
5. **Сверка.** Указать ссылку вручную или найти последний пост в профиле. Система проверяет соответствие аккаунта и начала подписи. Это не попиксельная сверка всех карточек. При доступном времени поста оно сохраняется; неизвестная дата не заменяется текущей.
6. **Результаты.** Добавить замеры с фактическим временем и источником. Режимы «24 часа / 7 / 30 дней» выбирают реальные снимки близкого возраста; исторические значения не восстанавливаются из сегодняшних. Для обращения указать постоянный ID/ссылку записи продаж — повторный ввод обновляет этап этой записи.

Очередь — состояние материалов и выпусков; задачи сотрудников ведутся в YouGile.

## Что действительно автоматизировано

- Сохранение очереди, версий, одобрений, календаря, ссылок, попыток, замеров и обращений в SQLite.
- Проверка очереди каждые 20 секунд, пока открыт завод. Выпускается только назначенная и одобренная версия с включённым автоматическим режимом. Общий режим изначально на паузе.
- Окно запуска — до 10 минут после назначенного времени. После более долгого пропуска нужна новая дата; очередь не выпускается пачкой после выключения ПК.
- Общий журнал и транзакция перед финальным действием: одна попытка выпуска, отсутствие автоматического повтора при неизвестном исходе, блокировка уже размещённого материала независимо от изменения подписи.
- Поиск последних постов в профиле Instagram/Threads и проверка указанной ссылки.
- Сбор через браузер запускается кнопкой. Он сохраняет только показатели, уверенно распознанные в отдельном окне статистики конкретного поста. Если интерфейс/доступ не подходит, показывает причину и оставляет ручной ввод. Плановый сбор через сутки/неделю/месяц и API-коннекторы не подключены.

Сообщение владельца о размещении, подтверждение соцсетью отправки и сверка поста браузером — разные состояния. Неизвестный исход отправки не возвращается в свободную очередь. Чтобы учесть уже вышедший пост, не нужно отправлять его заново.

## Данные и восстановление

`.tools/local/social-publisher/factory.sqlite3` и сопутствующие WAL/SHM-файлы находятся вне git, рядом с сессиями и диагностикой. Не удалять каталог при обновлении кода: он содержит ручные замеры и ссылки на обращения. Перед переносом закрыть инструмент и скопировать весь каталог; закрытый Chromium нужен также для переноса профиля.

В базе сохраняются версии текстов для конкретного выпуска и контрольные суммы карточек. Авторские исходники остаются в канонических файлах волта; готовые PNG не копируются в базу. После переноса пути к исходникам и комплектам должны оставаться доступными.

При запуске сервера незавершённая отправка получает состояние «Нужна сверка отправки», а черновики, существовавшие только в браузере, требуют новой подготовки. Чтение через CLI не выполняет восстановление и не сбрасывает состояние работающего сервера.

## CLI для помощника

```powershell
& .tools/venv/Scripts/python.exe -X utf8 .tools/projects/ananas-marketing/content/factory_cli.py list
& .tools/venv/Scripts/python.exe -X utf8 .tools/projects/ananas-marketing/content/factory_cli.py next
& .tools/venv/Scripts/python.exe -X utf8 .tools/projects/ananas-marketing/content/factory_cli.py brief <material-id>
& .tools/venv/Scripts/python.exe -X utf8 .tools/projects/ananas-marketing/content/factory_cli.py import .tools/carousel-out/<case> --material-id <material-id>
& .tools/venv/Scripts/python.exe -X utf8 .tools/projects/ananas-marketing/content/factory_cli.py summary
```

Команды CLI ничего не отправляют в соцсети. Управление публикацией идёт через защищённую локальную панель. «Новый материал» в CLI — `add --title "…" --source <markdown> --niche "…"`.

## Проверки

```powershell
& .tools/venv/Scripts/python.exe -X utf8 .tools/projects/ananas-marketing/content/test-content-factory.py
& .tools/venv/Scripts/python.exe -X utf8 .tools/projects/ananas-marketing/content/test-social-publisher.py
```

Тесты используют отдельные временные базы, локальные макеты соцсетей и браузер. Проверяются сохранение, независимые выпуски, снятие одобрения, защита от повторов и прерванной отправки, расписание, происхождение замеров, учёт обращений, формы, CSV и мобильная вёрстка. Они не подтверждают успешную отправку каждого будущего поста в живые соцсети.
