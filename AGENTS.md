## Сценарии

### Зафиксировать решение
**Триггеры:** «зафиксируй решение», «давай решим», «решено»

1. Определи тип: личное стратегическое → `life/decisions.md` / проектная гипотеза → `projects/*/hypotheses.md`.
2. Шаблон в `life/decisions.md`: контекст → решение → ожидание → чекпоинт → статус.
3. Подтверди одной строкой: куда записал.

### Зафиксировать гипотезу
**Триггеры:** «гипотеза», «давай проверим», «предположение»

1. Открой `projects/<проект>/hypotheses.md`.
2. Добавь по существующему формату файла (с `HYP-*` ID, ожиданием, чекпоинтом).
3. Если на её основе нужна работа — Володя сам заведёт задачу в YouGile.

### Быстро записать идею в указанную папку/файл
**Триггеры:** «запиши эту идею в папку...», «положи в ...», «закинь в ...», «сохрани в файл...»

1. Если Володя назвал папку/файл — используй её напрямую.
2. Если папка названа разговорно («в папку карт», «в Левшу», «в маркетинг») — найди ближайший подходящий файл через `_index.md` проекта и существующую структуру.
3. Не записывай новые идеи в `projects/*/backlog.md`: backlog заморожен, задачи живут в YouGile. Если это стратегическая идея — создай/обнови проектный материал, `hypotheses.md` или `life/decisions.md`; если это задача — кратко скажи, что её лучше завести в YouGile.
4. Если идеи пока нет в сообщении — спроси саму идею и целевую папку/файл одной короткой фразой.
5. После записи ответь одной строкой: куда положил и что именно зафиксировал.

### Статус проекта
**Триггеры:** «как дела с...», «статус...», «что по...»

1. Открой `_index.md` проекта — фокус, метрики, блокеры.
2. Открой `hypotheses.md` — что в работе, что подтвердилось.
3. Открой свежие материалы (marketing/, analytics/, meetings/) — последние артефакты.
4. **Не лезь в YouGile** — статусы задач Володя знает сам.

### Недельный / месячный обзор (по запросу)
**Триггеры:** «неделя», «ретро», «месяц», «обзор»

> Делается **только когда Володя попросит**. Vault не накапливает daily-логи, поэтому обзор собирается из проектных материалов и hypotheses, а не из дневника.

1. Спроси, какой проект и горизонт.
2. По проекту: что сделано (по артефактам — новые/изменённые файлы), что в гипотезах, что в `changelog.md`.
3. Паттерны: где буксуем, что повторяется.
4. Если нужен файл — `reviews/YYYY-WXX.md` или `reviews/YYYY-MM.md`. По умолчанию — ответ в диалоге.

### Отчёт в десятку (по запросу)
**Триггеры:** «отчёт в десятку», «отчёт Илюшину», «десятка»

Дедлайн **вс 23:59** — Володя помнит сам, vault не напоминает.
Шаблон: `life/ten-report/_template.md`. Я помогаю собрать черновик, когда попросит.

### Отчёт для клиента (трафик)
**Триггеры:** «отчёт для...»

1. Собери данные из папки клиента в `projects/traffic-freelance/clients/<клиент>/`.
2. Только результаты — без внутренних заметок.
3. Сохрани в `reports/` или выгрузи в Google Sheet.

### Inbox
**Триггеры:** «разбери inbox», «inbox»

1. Открой `inbox.md`.
2. Каждую запись раскидай по нужным файлам (decisions / hypotheses / client-intelligence / меняй проектные материалы).
3. Очисти inbox.
4. Если непонятно — спроси, не выбрасывай.

## Технические инструменты (что доступно в работе)

### Playwright (через venv)
- Установлен в `.tools/venv/` (Python 3.14, Windows). Команда: `.tools/venv/Scripts/python.exe <скрипт>`.
- Скрипты в `.tools/`:
  - `snapshot.py <url> <prefix>` — скриншоты desktop+mobile любого сайта (для анализа конкурентов)
  - `hero-shot.py` — снимок hero-секции нашего лендинга плёнки (desktop+mobile, без full_page)
  - `section-shot.py <selector> <out>` — снимок конкретной секции лендинга по CSS-селектору
- Выход: `.tools/snapshots/*.png`. Читаю через Read, вижу как картинку.
- Когда использовать: проверка как страница выглядит у пользователя (гибрид-режим), визуальный анализ конкурентов, контроль вёрстки после правок.

### Аналитические скрипты
- `.tools/film-avg-check.py` — пример обработки локального CSV из `analytics/`. Шаблон для будущих расчётов: парсинг → агрегация → перцентили → разбивка по периодам.
- Новые расчёты — писать как отдельный py-скрипт в `.tools/`, не складировать в Bash.

### MCP-серверы (нестабильно)
- **Google Drive** — `mcp__claude_ai_Google_Drive__*` — чтение/скачивание Google Sheets / Docs. Может отваливаться без warning; всегда иметь fallback на ручную выгрузку.
- **Google Calendar** — события, расписания.

### Codex-skills (плагины)

## Гигиена системы (раз в месяц)

При фразах «давай прибрёмся / ревью системы / гигиена» — пройти по чек-листу:
1. Аналитика: найти пары `*-YYYY-MM-DD.md` за разные даты с одинаковым префиксом → старшие пометить в шапке `> Устарело, актуальная версия → [...]` или переместить в `_archive/`.
2. Память: пройти `memory/MEMORY.md`, проверить что каждая карточка ещё актуальна; слить дубли (`*_v2.md` после устаревания `*.md`).
3. `_index.md` проектов: проверить, что нет broken-ссылок (`grep "](.*\.md" | check exists`). Сгруппировать по статусу: активное / в работе / архив / референс.
4. `.tools/`: проверить, что скрипты задокументированы — иначе через 3 мес сам не вспомнишь.

## Работа с историей и гипотезами

### Правила

**При любом изменении системы** (новая папка, новое правило, изменение процесса):
→ Добавь запись в `system/changelog.md`

**При обсуждении идей по проекту** (новый канал, новый оффер, изменение цены):
→ Предложи зафиксировать как гипотезу в `hypotheses.md` проекта

**При обсуждении жизненных решений** (сменить фокус, начать/бросить проект):
→ Предложи записать в `life/decisions.md`

**При результате работы по детейлингу или системе:**
→ Предложи добавить тему в `ai-infobiz/content-pipeline.md` (кейс / пост / антикейс)

**При упоминании обратной связи от клиентов детейлинга** (вопрос, возражение, похвала, отказ):
→ Запиши в `detailing-samara/client-intelligence.md`

**После смены наблюдения у стойки приёмщика:**
→ Минимум 1 запись в `client-intelligence.md` (вопрос / возражение / похвала / отказ / паттерн)

**Никогда:**
→ Не предлагать «добавить задачу в tasks.md» — задачи в YouGile, Володя заводит сам.
→ Не предлагать «активировать на неделю» / понедельную пересборку.
→ Не запускать утренний/вечерний ритуал.
→ Не удалять записи из истории, не редактировать старые (только добавлять ретроспективу).
