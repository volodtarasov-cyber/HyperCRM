# Сайт, шаблон, дизайн — фаза 1 курса, уроки 5–7

> Импортированная внешняя теория курса «Цех Васина». Индекс → [_index.md](_index.md).

## Сайт под завод: что собирается

- **Для трафика нужен только блог**, но без главной и коммерческих страниц не обойтись: поисковик должен понять категорию сайта — статейник, агрегатор, сайт компании.
- **Автораспаковщик** собирает сайт на Next.js (стартер) или только блог; до выката всё закрыто от индекса, даже если домен подключён.
- **Сайт уже есть** (Битрикс, WordPress, Тильда, самопис): сайт не переносят, трогают только блог. Правила для агента: URL не менять; сначала локально, потом прод; ничего не удалять; спросить про GitHub; отдельный sitemap для блога, если основной генерирует CMS. Конструктор без доступа к коду и разметке — тогда блог собирается на своём сервере и подшивается к домену подпапкой.
- **Можно ставить частями:** «в SEO-машине есть <система> — примени её к моему сайту и покажи, что предлагаешь изменить» — для семантики, перелинковки, разметки, мониторинга, обложек.
- **Промпт «аналитика ниши → два ТЗ»** (урок 1.5): аудитория по Шварцу и JTBD → карта запросов в два ведра (инфо для блога, коммерческие для денег-страниц) → конкуренты по выдаче и sitemap → Wordstat → структура и стратегия → чекпоинт «утверждаю?» → ТЗ на дизайн и ТЗ на сборку (Next.js App Router + SSG, MDX в `content/blog`, статьи кладутся пачками без правок кода). Деньги-страницы и блог — разные сущности, не смешивать.

## SEO-требования к шаблону

**Индексация.** CSS/JS в robots.txt не блокировать. `Disallow` не убирает страницу из выдачи — только `noindex` на открытой для обхода странице; если сначала закрыть в robots, а потом поставить noindex, поисковик его никогда не увидит. Sitemap — только канонические URL, `lastmod` меняется только при реальной правке; новая статья попадает в карту автоматически.

**Глубина:** пагинация листинга обычными ссылками (`/blog/page/2`), а не «показать ещё» и не бесконечный скролл; до любой статьи ≤ 3 кликов от главной.

**Дубли:** все версии домена → 301 на одну; self-canonical на всех шаблонах; параметрические URL (`?utm_`, `?from=`) → canonical на чистый адрес + noindex + вне sitemap. Синонимизация от дублей не спасает: поисковик сверяет цепочки из 3–5 слов, а массу почти-дублей наказывает на уровне всего домена.

**URL:** латиница нижнего регистра через дефис, иерархия = структура сайта, хлебные крошки с `BreadcrumbList`; без года для вечнозелёного материала; смена только через 301.

**Заголовки:** title и H1 об одном (поисковик собирает пул кандидатов в заголовок выдачи и выбирает по кликам); ключ — в начале, в URL и в первых 50–100 словах; ровно один H1, иерархия без пропусков; CTA-баннеры — блоком `<div>`, не заголовком. Длина title считается в пикселях (~600), а не в символах.

**Скорость:** первым чинится время ответа сервера; мобильные метрики весят больше; первый экран сразу отвечает на запрос.

**Микроразметка** не поднимает позиции и не гарантирует сниппет. Минимум: главная — `Organization` + `WebSite`; статья — `Article`/`BlogPosting` + `BreadcrumbList` + `Person`; листинг — `CollectionPage`/`ItemList`. `FAQPage` — только при видимом блоке вопросов: Google почти перестал показывать FAQ-сниппеты. Сущности страницы лучше собирать через `@graph` со ссылками `@id` (эталон — Лайфхакер). Размечать только видимое.

**Обязательные мелочи:** Open Graph (`og:image` — абсолютный URL 1200×630); осмысленные имена файлов картинок; уникальный alt, не копирующий H1; RSS при регулярной публикации.

## Шаблон статьи и E-E-A-T

H1 → короткий ответ → автор с ролью и живым фото → дата публикации и видимое «Обновлено» + машиночитаемый `dateModified` → оглавление → разделы H2 (служебные блоки заголовками не делать) → FAQ, где уместно → блок «Источники» (2–5 ссылок; у семи разобранных топовых сайтов его нет ни у одного — свободное место) → «Похожие статьи» с настоящими обложками → CTA. Нормы объёма в словах нет — объём задаёт задача.

Эталоны из урока: Петрович (глубокий URL-кокон, видимая дата обновления, каталог с пагинацией), Т—Ж (120 внутренних ссылок, альты), Лайфхакер (разметка `@graph`, статья 2018 года держится в топе за счёт регулярного рефреша), Совкомбанк (инфо-статья → 51 партнёрская ссылка в теле с маркировкой = модель монетизации).

## Чек-лист сборки сайта (сводка 9 групп)

Структура (главная с оффером, хабы = кластеры, автор, «о проекте», контакты, юр-страницы, нормальная 404) · дизайн (16px+, ширина текста ~700px, одна палитра) · конверсии (CTA на каждой статье, путь инфо-статья → хаб → действие, минимум полей в форме, цели Метрики, реклама не в первом экране) · скорость и мобильность · право (политика, согласие у каждой формы, реквизиты, cookie, слот под маркировку рекламы) · SEO-техника · разметка · E-E-A-T · финальная самопроверка с отчётом «пункт → выполнено / нет / почему».

## Дизайн

- По умолчанию сайт нейтральный; дизайн — отдельный этап после распаковки и до выката. Четыре шага: направление → дизайн-система токенами → компоненты и страницы из системы → придирчивая вычитка.
- Скиллы, которыми пользуется автор: `design-taste-frontend`, `high-end-visual-design`, `ui-ux-pro-max`, `redesign-existing-projects`, `impeccable`.
- Приметы «ИИ-дизайна»: один оттенок по всему сайту, надзаголовки капслоком над H1, две узкие колонки на телефоне, липкая панель из 3–4 кнопок, эмодзи и самодельные иконки. Вместо этого: нейтральная база + один акцент только на действии; один открытый набор иконок.
- Прототип рисуется снаружи (Claude Design, Lovable, Google Stitch), агенту отдаётся только оформление — сайт не переписывается. Промпт на дизайн-ТЗ блога заранее описывает контракт данных завода: title, description, одна категория, теги, обе даты, автор из справочника, обложка 16:9, время чтения, оглавление.
- Дизайн не ломает скорость, иерархию заголовков, читаемость (65–75 символов в строке, 16px, интервал 1,6) и форму заявки.
