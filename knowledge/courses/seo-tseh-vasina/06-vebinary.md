# Вебинары, видеоуроки и доп-модули пакета

> Импортированная внешняя теория курса «Цех Васина». Индекс → [_index.md](_index.md). Расшифровки целиком — `D:\Курсы\ИИ SEO курс\ИИ SEO курс\_transcripts\`.

## Вебинар 1 — разбор распаковки (39 мин)

- **С сайтом работают только локально:** проверка → сверка с GitHub, не было ли правок из других сессий → коммит → выкат. На боевой хостинг агенту доступ напрямую не дают.
- **Первая статья — демонстрация, не эталон.** Аудит 6.1 с разбором топа говорит, какой длины и с какими таблицами и инфографикой писать в этой нише; после него завод нужно «научить» писать хорошо и при желании переписать первые статьи.
- **Если блог уже есть:** промпт 6.1 смотрит sitemap и не пишет по уже закрытым темам. Улучшение старого: проверить вёрстку по чек-листам, прогнать топ-20 статей (по Wordstat) через разбор топа и скилл текстов.
- **Фактчекинг в базовом заводе выключен** — включается под нишу: проверять только по доверенным сайтам, по своей базе, рискованное — себе на одобрение в Telegram.
- **Обновления пакета меняют только базу знаний** — персональные настройки сайта не слетают.
- **Сложная многоуровневая структура рубрик:** ИИ сделает «фигню» — верхний уровень архитектуры автор валидирует у живого SEO-специалиста, при необходимости покупая экспертизу.
- **Большая база документов** (бюллетени, справочники): при сотнях тысяч файлов Obsidian-заметок не хватит — нужен RAG-поиск.
- **Тильда:** через браузер агент работать не должен — медленно и жжёт токены. Блог — на поддомене или, лучше, в подпапке `/blog` через Cloudflare-прокси на VPS.

## Вебинар 2 — вопросы по ходу (39 мин)

- **Как автор ведёт несколько сайтов:** у него папка проектов (~50 папок, у каждого свои правила). Новому домену говорит агенту: «разверни мне SEO-завод, как на таком-то сайте, создай новую папку» — и возвращается через час. Так развёрнуто 15 сайтов. То есть **каждый сайт — своя развёрнутая копия завода**, общая — только глобальная память агента («второй мозг»), которая знает, где что лежит.
- **Несколько партнёров в одном городе с одной семантикой:** разные компании с разными ИНН могут вести каждая свой блог и конкурировать за выдачу; у одной компании с филиалами — один блог со списком филиалов. Уникальность — разные корпуса авторов как референс стиля.
- **Своя база фактов до написания** (характеристики авто, номенклатура): персональная настройка промпта — «перед статьёй сначала смотри в базу знаний как первоисточник».
- **Картинки:** замена на реальные фото — это обновление статьи, хуже не будет. Чужие фото — юридический риск.
- **Соцсигналы:** нарезки в Reels и Shorts дают переходы, Метрика их видит — консенсус SEO-специалистов, что это помогает. Копировать те же тексты в Дзен, скорее всего, нельзя — нужна адаптация.
- **Метрику ставить сразу**, Яндекс сам её рекомендует; не выкладывать сайт с битой вёрсткой, если на домене уже был живой сайт с заявками.
- Разведка ниши через скилл — беглый анализ (≈10 запросов), а не стратегия. Главное в вердикте: есть ли массовые инфо-запросы и не забита ли выдача агрегаторами; ориентир конверсии инфо-трафика в заявку — 0,3–0,5%.

## Видеоуроки, которые дополняют тексты

- **Итог распаковки (24 мин):** после установки — пульт со светофором, отчёт для автора, очередь тем. Дальше работа идёт обычными фразами в окне агента: «в SEO-машине есть правило для шаблона — покажи», «сравни мой блог с рекомендациями базы знаний и выпиши, чего не хватает». Для чужой CMS — коннектор: завод генерирует MDX или JSON, CMS забирает (FTP-папка, вебхук). Apify нужен, чтобы парсинг шёл не на токенах подписки.
- **Создаём сайт (19 мин):** для стратегии и архитектуры — самая тяжёлая модель, для кода по ТЗ хватает средней. В папке проекта до сборки: `CLAUDE.md` с правилами, карта проекта, changelog, `hot.md` — краткий журнал сессий, раз в неделю ужимается. Семантику положить до сборки, чтобы она учлась в архитектуре. Агента останавливать по этапам: сначала одна страница или цветовая схема.
- **Шаблон статьи (15 мин, эксперт):** каталог — крошки, один H1, главная статья, карточки с категорией, датой, временем чтения, пагинация цифрами. Статья — индикатор прочтения, кнопка «наверх», плавающее оглавление, краткий ответ сразу под H1, автор с должностью, даты публикации и обновления, главное изображение с подписью, источники в конце, блок «читайте также» до 10 карточек, комментарии с антиспамом. Проверка — плагин SEO META in 1 Click и Rich Results Test.

## Доп-модули из пакета завода (`seo-factory/knowledge/karta-potoka/uroki/`, в папке курса их нет)

- **Дорожная карта блога на год (эксперт, 19 мин):** 0–3 мес — фундамент (техничка, шаблоны, авторы, первые ссылки, живой соцтрафик); 4–6 — диагностика; 7–12 — масштаб. Журнал публикаций и **аварийный выключатель** при серии из 3 одинаковых ошибок. Claude и Codex часто плодят дубли с GET-параметрами. Нет трафика через 3 месяца — ограниченный тест в Директе на статьи из топ-100 на две недели; пустой ссылочный профиль — малая ссылочная кампания на точки роста, оценка через 6–8 недель, без результата бюджет не поднимать. Раз в 7–10 дней — 5–10 свежих статей «глазами читателя» и «глазами робота».
- **Воронка по сырым логам Метрики:** Logs API тем же токеном, воронка по уникальным `clientID`, события-хиты, которых нет в целях. Логи отвечают «где», Вебвизор на найденном шаге — «почему». Решение принимается на шаге, где прошло ≥ 100 человек; одна правка за раз, замер через 2–4 недели. Пример автора: 88% открывших квиз не делают первого клика — одна правка экрана против трёх месяцев новых статей.
- **Админка, чтобы заказчик правил сам** (Next.js + Payload + Postgres): таблица «страница → что правит заказчик → раздел админки или код», поля засеяны текущими текстами, у каждого поля человеческое описание, правка доезжает до живой страницы без деплоя, аудит «мёртвых пультов» — у каждого поля должна быть страница-читатель. Не конструктор: порядок блоков остаётся в коде. Проверка — `curl` по боевому адресу, а не браузер.
- **Аудит сайта по семи осям:** вёрстка, скорость и вес, безопасность (шесть заголовков; CSP только Report-Only), SEO-техничка, доступность (контраст 4,5:1 на обеих поверхностях, цели 44 × 44 px), правда витрины (сверщик цен с источником, блокирует сборку), мёртвые пульты CMS. Факт о сайте даёт живой сайт, а не репозиторий; каждую находку перепроверять фактом до правки.
- **Как следим за заводом:** первый месяц смотреть только индексацию в Вебмастере («добавлено» и «в поиске» растут, вторая тянется к первой); дальше — мониторинг запросов. Второй сайт автора, собранный старой версией завода без Wordstat, потерял 287 страниц — статьи писались без учёта спроса.
