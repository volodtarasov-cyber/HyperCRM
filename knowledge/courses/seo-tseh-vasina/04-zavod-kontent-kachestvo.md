# Завод, контент, качество — фазы 1 и 3 курса, уроки 5, 12–13

> Импортированная внешняя теория курса «Цех Васина». Устройство конкретного пакета, который стоит у нас, — в его собственных `docs/` (`D:\SecondBrain\seo-factory`), паспорт → [.tools/README.md](../../../.tools/README.md#вне-волта). Индекс → [_index.md](_index.md).

## Из чего состоит завод

- **Контент-фабрика:** бриф → писатель (инфостиль по Ильяхову) → редактор-фактчекер (серьёзная проблема → черновик) → гейт качества без ИИ (title ≤ 60, description ≤ 160, чистый слаг, дубль заголовка → в черновик) → очередь → публикатор.
- **SEO-агент, модули M1–M8:** M1 семантика → бэклог · M2 техаудит (дельта к прошлому снимку) · M3 позиции · M4 E-E-A-T (балл 0–100 по статье) · M5 перелинковка и «сироты» · M6 структура конкурентов (не их позиции) · M7 каннибализация · M8 актуализация.
- **Советник:** дешёвая модель (DeepSeek) только подсказывает и шлёт в Telegram, в прод ничего не пишет. Тексты всегда пишет Claude или Codex.
- **Три контура расписания:** launchd (Mac) или cron (Linux) — там, где залогинена подписка, оттуда идёт генерация; GitHub Actions — для скриптовых модулей без нейронки. Пока машина с подпиской включена, завод пишет статьи наперёд в очередь; публикатор выкладывает их по расписанию уже без нейронки.
- **Темп:** ≤ 5 статей в день на сайт, наращивать постепенно, не кратно. Резкий скачок 5 → 10 читается как автогенерация и тормозит индексацию.
- **Codex или Claude — почти без разницы:** правила в `CLAUDE.md` и `AGENTS.md` совпадают слово в слово, завод сам зовёт `claude -p` или `codex exec`. Отличаются установка, файл правил, скиллы (в Codex — «прочитай файл и работай по нему») и настройка MCP.

## Окружение: один раз на все сайты

Окружение = правила + скиллы + коннекторы (MCP) + карта проекта. Глобальное ставится один раз и **служит всем сайтам**; в каждый новый сайт добавляются только `CLAUDE.md`, `docs/_map.md`, `docs/changelog.md`.

- Три правила «поставил навсегда»: `no-hallucinations` (сначала проверить инструментом, иначе честно «не удалось верифицировать»), `report-format` (P1 индексация / P2 ранжирование / P3 улучшение, рекомендация — конкретное действие), `subagent-patterns` (толстый промпт: субагент не видит правил; каждый пишет в свой файл; не больше 5 одновременно).
- MCP: Context7 (свежая документация) + chrome-devtools (живая проверка сайта).
- **Вход по подписке:** если в окружении лежит `ANTHROPIC_API_KEY`, инструмент молча спишет деньги по API мимо подписки.
- Стек инструментов по деньгам: бесплатный фундамент (GSC API — один сервисный аккаунт на все проекты; PSI/Lighthouse; advertools) → дешёвый поиск (Exa → Firecrawl → Perplexity, ~$24/мес) → платная разведка (Ahrefs, Keys.so, Arsenkin, TopVisor) только когда проект зарабатывает.
- «Позиции» бывают двух видов: средняя по реальным показам (GSC, Вебмастер) и снимок бота в момент проверки (TopVisor, Keys.so). В отчёте их не смешивать. API Вебмастера позиции не отдаёт вовсе — только показы, клики и CTR.

## Контент под «усилие»

- **contentEffort:** поисковик моделью оценивает, насколько дорого повторить материал. Рычаги: свои данные («посчитали по 312 случаям»), свои медиа вместо стока, заголовок-факт вместо заголовка-обещания, честные ограничения, структура и глубина вместо длины.
- **Information Gain:** награда за новое сверх топа; рерайт чужих статей ≈ 0.
- **Провенанс — красная линия:** любая цифра, дата или вердикт, которых нет во входных данных → «данных нет» и вывод без числа.
- **Стоп-лист фраз:** «в современном мире», «в наши дни», «на самом деле», «в действительности», «шаг за шагом», «играет важную роль», «не секрет, что», «стоит отметить, что», «важно понимать», «в целом», «в заключение» и т.п.
- **Логика статьи эксперта:** кластер с частотностью и срезом → LSI-слова → 2–3 конкурента, ранжирующихся по большинству запросов кластера → длина и картинки по их среднему (+15% картинок; есть таблица или инфографика хоть у одного → делать обязательно) → H1 с самым частотным ключом в начале, не дословно как у конкурентов → структура чуть полнее лучшего конкурента → короткий ответ сразу после H1 → блок «Источники».
- **Под каждым H2** сначала 1–2 предложения прямого ответа — для выдачи и для ИИ-ответов.

## Фактчекинг

- Проверяются только **изменяемые факты**: цены, тарифы, нормы, сроки, даты, правила, номера законов — то, на чём читатель может потерять деньги, время или получить отказ.
- **Три вердикта, не два:** подтверждено → публикуем; опровергнуто → блокируем; не проверено → публикуем, но пишем в журнал статьи. Бинарная логика останавливает конвейер на верных статьях (живой случай — закрытый для робота сайт перевозчика).
- **Упавший прогон проверки = блокировка,** иначе первая же поломка превращает гейт в штамп.
- Источники по порядку: официальный сайт → госпортал или нормативный акт → отраслевой орган → крупное профильное издание. Блоги, агрегаторы и ответы нейросетей источниками не считаются.
- Топ 5–8 критичных фактов на статью. Раз в месяц подкладывать заведомо ложный факт и проверять, что гейт его удержал.
- Маршрут подходов: свои глаза по темам-триггерам → автопроверка с поиском → своя библиотека документов (с датой у каждого файла) → RAG.

## Проверка машины, а не только сайта

- Почти любая поломка завода **молчит:** не собралась семантика — статьи пишутся не про то; пропал `seo/keymap.json` — гард дублей выключается без сообщения; не сохранилось расписание — тишина выглядит как «всё хорошо».
- **Правило приёмки:** система рабочая, только если это видно на файлах — файл, строка конфига или вывод команды.
- `doctor` — поедет ли (конфиг, ключи, нейронки); `checkup` — работают ли 14 систем и оставляют ли следы; `self_audit.py` — что осталось доделать; 14 промптов-чек-листов — то, что кодом не увидеть (вёрстка, стиль, осмысленность кластеров). Зелёный `doctor` не доказывает, что статьи выходят.
- Не включать автопилот, пока падают тесты git-безопасности публикации.

## Веб-панель

Одна страница: вердикт словами в первой строке → публикации против плана и календарь 30 дней → запас тем **в днях** → трафик Яндекса и Google на одном графике → позиции → аудит → здоровье. Нет источника — «не подключено», **ноль вместо отсутствующих данных запрещён** (у автора панель месяц показывала «0 в очереди» при работающем конвейере). Ритм: утром 30 секунд на вердикт; раз в неделю 20 минут — календарь, запас тем, рост топ-10; раз в месяц — свежий аудит.

## Доказательный аудит T → E → E → A → поведение

Доверие и техника (HTTPS, robots, один домен, canonical, нет мусора в индексе, исходящие не на спам, CWV) → опыт (свои данные и медиа, уникальность — фраза в кавычках в поиске) → экспертиза (тема сайта одной фразой, нет выбросов, покрытие терминов топа, коконы) → авторитет (ссылки со страниц с трафиком, анкоры, бренд, авторы с био) → поведение (заголовок выполняет обещание, первый экран, CTR-аутлайеры). Провал фундамента сверху не компенсируется.

## Парсинг, когда сайт не читается

Лестница от дешёвого: штатное чтение → `scrapling extract get` → `stealthy-fetch --network-idle --solve-cloudflare` → браузер под агентом → платный анблокер. Половина «сайт недоступен» — это не блок, а JS-рендер. Блок по IP маскировкой не лечится. Jina Reader из РФ отвечает 451.
