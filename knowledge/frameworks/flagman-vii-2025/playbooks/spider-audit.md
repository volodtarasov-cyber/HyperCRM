# Прикладной аудит через Screaming Frog по курсу

**Тип:** импортированный процесс. **Источники:** полностью прочитанные [часть 1](../lessons/v-15952e086caf.md) и [часть 2](../lessons/v-c64ff7102150.md). Цены, лимиты и интерфейсные варианты относятся к записи, внешняя актуализация не проводилась.

## 1. Определить область и ресурс

Нужны домен/раздел/список и цель: весь аудит, контроль внедрения, Sitemap, конкретные элементы. Выбрать Spider для обхода или List для своего пула. Решить, выходить ли за папку, включать ли поддомены и внешние ссылки.

Настроить память/SSD-хранилище, разумную скорость и нужные поля. JavaScript включать для соответствующего вопроса: это дороже по времени. Не увеличивать потоки без учёта нагрузки сайта. Пороги предупреждений программы — конфигурация, а не автоматически обязательные нормы поисковика.

## 2. Сохранить базовый обход

Собрать URL, коды, индексируемость, meta robots, теги и внутренние связи. При нужде подключить Sitemap и разрешённые API Analytics/Search Console, с понятным периодом и сбором новых URL. Без этого вывод «сирот нет» неполон.

Сохранить выгрузку/проект. Для работы программиста это состояние «до», с которым затем сравнивается «после».

## 3. Проверить основные группы

- **Коды/ссылки:** 4xx/5xx, цепи, нецелевые редиректы, реальные From/To. Разобрать причину и адреса, не превращать все ответы в 200.
- **Теги:** отсутствие/дубли/несколько элементов, соответствие страницы. Длину оценивать по смыслу и заданной настройке; несколько H1 лектор не считает автоматически критичными.
- **Дубли:** полные и близкие с выбранным порогом, нужная область индексируемых страниц. Параметры разбирать с учётом их функции. Batch Unique Checker упомянут для близких дублей.
- **Основное содержание:** отделить шаблон через include/exclude ID/class. Проверить селектор на реальных страницах, затем сравнивать объёмы одного типа. Малое число слов — сигнал исследования, не универсальная причина удалить.
- **Листинги:** повторяющийся класс карточки в Custom Search → количество совпадений → пустые/малые наборы. Проверить, что класс действительно соответствует одному товару/элементу.
- **Счётчики/старые данные:** поиск ID аналитики/телефона/фразы → страницы без нужного или со старым. Наличие кода не доказывает получение событий; исключения могут быть намеренными.
- **Изображения/разметка:** размеры и доступность, включённый сбор structured data, ошибки/предупреждения по конкретным HTML. После включения нового сбора повторить обход.

## 4. Проверить структуру и результаты

Посмотреть глубину клика, входящие ссылки и дерево обхода. Важное сделать достижимым с главной/основного раздела. Папки URL и кликовую глубину не считать одной величиной.

По источникам Sitemap/Analytics/Search Console найти Orphan Pages. По сессиям/кликам за минимум три месяца сформировать кандидатов без трафика; проверить полноту данных, индексируемость и роль страницы. В записи допускает доработку/ссылки либо удаление конкретной ненужной статьи. Сырой список не является автоматическим приказом удалить всё.

При необходимости PageSpeed API собрать аккуратно с учётом лимитов и нагрузки самого обхода. Предварительный сниппет использовать для оформления, не как обещание будущей выдачи.

## 5. Подготовить действие и сравнение

Выборку перевести в [понятное ТЗ](developer-handoff.md): что, где, почему, нужный результат, исполнитель и проверка. Проверить после внедрения тем же сопоставимым обходом. Исправление файла/кода и последующая переиндексация — разные события.

Опционально протестировать robots внутри программы; это не меняет сервер. Экспорт Sitemap делать только по подходящим доступным HTML без noindex, затем разместить и учитывать дальнейшее обновление.

**Выход:** сохранённый обход, адресные выборки и проверяемое ТЗ. **Приёмка:** область/настройки/источники известны, данные получены, селекторы проверены, автоматические сигналы осмыслены, «до/после» сопоставимы. Фактический аудит чужих сайтов этой обработкой курса не выполнялся.
