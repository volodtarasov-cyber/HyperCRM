# Актуализация гибридной структуры по курсу

**Тип:** импортированный процесс «Флагмана VII», сборка по полностью прочитанным урокам; не подтверждённый результат применения агентством.
**Источники:** [вступление](../lessons/v-7749ac6db5a1.md), [теория](../lessons/v-9dcdc0efa52d.md), [практика](../lessons/v-9c241fab316d.md), [сохранение старых страниц](../lessons/v-258ff6b4e491.md), [ручная доработка](../lessons/v-07982b6a43b3.md), [задание](../lessons/v-99c1a82afe00.md).

## Вход и результат

Вход — [расширенный каркас](structure-draft.md), статус существования каждой ветки на своём сайте и легенда. До начала убедиться в достаточном охвате: здесь основная работа очищает и упорядочивает, а не заменяет сбор.

Выход — чистовой общий список маркеров с понятной ролью будущих страниц, сохранённой связью с существующими URL и обновлёнными частотностями. Полное ядро всех запросов каждого кластера в основной процесс не входит.

## 1. Разобрать неопределённое и проверить названия

Для каждой ветки из «распределить» посмотреть выдачу и реализацию на похожих сайтах. Решить, относится ли она к коммерческой услуге, информации, коммерческому фактору или чужому бизнесу. Например, образец договора может стать приложением/разделом документов в ТЗ, а не обычной семантической посадочной.

Быстро прочитать весь список, особенно слишком общие и длинные названия. Для сомнительного запроса открыть подходящие страницы и получить их видимость, выбрать ясный маркер нужного интента. При слабых данных одного URL смотреть другие. Рекламные результаты не использовать как органический топ; URL очистить от поисковых меток.

Для повторяющихся географических форм выбрать логичный частотный шаблон по достаточно крупному городу. Не принимать случайную разницу малых месячных чисел за основание разных названий.

## 2. Получить полуавтоматические данные

Свести коммерческие и информационные маркеры в два проекта WordKeeper в целевом регионе. Хабы и разделы коммерческих факторов не копировать. По записи собрать последовательно:

- Частотности за месяц, включая самый точный вариант; годовой срез особенно нужен для сезонности.
- Коммерциализацию и основные слова тематики/топа.
- По необходимости оптимальную словоформу и дополнительные показатели.
- Кластеризацию **Hard для коммерции**, **Soft для информации**.

Экспортировать. Проверить сортировками пустые поля и собрать пропуски: отсутствие результата измерения не является нулём. Альтернативная тематическая классификация — Just Magic, затем сопоставление ВПР. Названия тарифов в уроке не считаются текущими условиями покупки.

## 3. Исправить группы и типы намерения

По группам выбрать подходящие маркеры, не подменяя смысл максимумом частотности. Подозрительные слияния проверить выдачей через Arsenkin Tools и непосредственным просмотром страниц; при сомнении Яндекса сравнить Google. ИИ использовать как дополнительное объяснение, не как окончательного классификатора.

Тематические слова помогают обнаружить другое значение знакомой фразы. Коммерциализация помогает найти возможные информационные ветки в коммерции и наоборот. Ориентир автора около 30% — **сигнал проверки**, не команда автоматически переносить. После переноса запросов в другой список повторить нужную группировку.

Нули сохранить для дальнейшего решения, если нет отдельной причины убрать явный мусор. Сначала производятся страницы с подтверждённым спросом; нулевые кандидаты могут быть пересмотрены по году или в сезон. Они не получают автоматического поручения на создание.

## 4. Сохранить действующие страницы

Перед слиянием найти каждый маркер в основной карте по полному совпадению. Если новый маркер лучше старого, но страница уже существует, **переименовать существующую ветку с сохранением её статуса**, а не оставить нового синего кандидата и потерять старую жёлтую.

Если группа содержит несколько действующих URL, новичок их не склеивает и не удаляет. Сохранить, при необходимости пометить для отдельного анализа. Опытному потребуется выяснить запросы, силу страниц и реальное взаимное влияние. Массовый кластеризатор этого решения не принимает. Для нового сайта развилка не применяется.

## 5. Осмысленно доработать общий список

Теперь работать только с общей картой, старые таблицы не синхронизировать после каждого перемещения. Прочитать каждую ветку и определить её место на сайте. Уточнить группировку, регистр, отделить диаметр от глубины, обслуживание от видов услуги. Проверять смысл и реализации конкурентов. Точечный найденный пробел можно добавить, не превращая этап в повтор всего сбора.

Внутри логических групп сопоставить выдачу. Отделить сильно пересекающиеся запросы в меньший список, если общий обзор перегружен. Смотреть, что ранжируется: главная, отдельная услуга, страница цен или статья. Нельзя производить несколько одинаковых страниц только потому, что сервис не слил маркеры.

Авторские ориентиры: 4–5 общих URL усиливают основание объединения, при трёх нужно думать. Несколько самостоятельных частотных смыслов и конкурентный регион чаще склоняют к дроблению; один сильный и несколько слабых — к объединению. **Во всех развилках первичен интент.** Слияние уменьшает риск каннибализации, дробление даёт отдельные Title/H1/URL.

Согласовать актуальность с владельцем на разговоре, пояснив значение охвата. Категорически неподходящее пометить отдельным цветом. Смежные информационные темы могут быть полезны и без оказания соответствующей услуги; коммерческое обещание другого продукта автор сам считает сомнительным экспериментом.

## 6. Повторно измерить чистовой состав

Из окончательного общего списка сформировать коммерческие/информационные таблицы и заново собрать месячные **и годовые** частотности в WordKeeper. По ним дальше сопоставлять страницы, готовить теги и порядок создания. Логические узлы группировки не подменять отдельными посадочными.

## Приёмка

- Для каждой ветки понятно намерение и место на сайте.
- Автоматические ошибки и смешанные смыслы рассмотрены, а не скрыты.
- Новая формулировка не потеряла связь с действующим URL.
- Сезонный ноль, пропуск измерения и отсутствие бизнес-интереса различены.
- Карта и её итоговые таблицы содержат один согласованный состав.
- Старые страницы не удалены/склеены только по результату группировки.

После внедрения запросы могут закрепиться за иными URL, чем ожидалось. Сам автор считает последующую проверку и дооптимизацию нормальной частью работы. Текущий результат позволяет перейти к сопоставлению страниц и тегам, но не гарантирует идеального закрепления всех запросов.
