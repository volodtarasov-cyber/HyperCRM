## 00:00–04:06. Как помочь обнаружить готовые страницы

Для отдельного подготовленного, но неиндексируемого пула создать свою XML-карту и добавить в Вебмастер/Search Console. Для Google предлагает ссылки с авторитетных часто обходящихся площадок и Indexing API; считает API более пригодным уже индексируемому сайту. Область применения API в этом уроке не проверяется вне записи.

Для Яндекса связывает Метрику и Вебмастер, направляет рекламу/посетителей на готовые страницы. Сам оговаривает обратную сторону: сигналы посещений могут открыть мусорные параметры/ошибочные URL. Это предложение автора, не гарантированная причина включения в индекс.

Рендеринг JavaScript сравнивает через **Google → проверка расширенных результатов → HTML** и **Яндекс Вебмастер → проверка ответа сервера**. Ограничение первых 50 тысяч символов и степень рендеринга относятся к демонстрации. Поисковые системы/инструменты не объявляются неизменными по этому старому примеру.

## 04:06–10:16. Скрытие частей документа

Показывает/описывает несколько способов и собственные тесты:

- PHP-ветвление по User-agent Яндекса/Google, которое сам называет клоакингом.
- Post-Redirect-Get для ссылок: по его объяснению, роботы не отправляют POST форм; ссылается на статью Доктора Макса. По отсутствию тестового адреса в поиске демонстрирует свой опыт, не всеобщую гарантию.
- JavaScript/AJAX/WebWorker для части контента, отмечая ограничения рендеринга Яндекса.
- AJAX-ресурс в папке, заранее закрытой в robots.txt; называет важным, чтобы запрет уже был известен роботам, в примере минимум две недели. Предлагает раздельные секции роботов.
- CSS `content` с `::before/::after`, перенос текста в CSS; считает затруднением и для типовых парсеров.
- Текст картинкой; выражает уверенность, что обычно так он не учитывается. Оценка «95%» — мнение лектора, не наш результат.

Полные PHP/JS-конструкции и точные ссылки находятся в статье/раздатке, не восстановлены по экранным указателям транскрипта. Отсутствие конкретной строки в поиске не доказывает, что все другие способы всегда будут вести себя так же.

## 10:16–16:28. Целые страницы и частые ошибки

Для исключения обсуждает meta robots, X-Robots-Tag, robots.txt, 410, запрет доступа .htaccess, Clean-param для Яндекса. Различие эффективности по поисковикам — трактовка лектора. Из XML-карты убирать удалённые/непредназначенные к индексированию адреса, чтобы не задавать конфликтующий набор обхода.

Проверить, не остался ли полный запрет `Disallow: /` после разработки. **robots.txt публичен**: секретный путь в нём не становится защищённым. Для закрытого доступа лектор также упоминает пароль/.htaccess; исключение из индекса не подменяет аутентификацию.

Ошибка незакрытого noindex в примере скрывает гораздо больше контента, чем задумывалось. Невалидное закрытие обычного HTML-тега некоторые анализаторы обрабатывают иначе. Проверять конкретный код и результат инструмента, не путать пустой отчёт с отсутствием текста на странице.

## 16:28–20:39. Реальный код ответа

Нужный документ — 200; несуществующий — 404; редирект отдаёт соответствующий 301/302. Красивый текст ошибки с 200 — soft 404, в примере агрегатора приводит к исключениям/МПК. Проверять нормальный URL и заведомо неправильный.

Лектор использует собственный **инструмент кодов ошибочных страниц** и **checkmy.ru → проверка ответа сервера**. Разбирает двойные слэши, index.php/html, знак вопроса, точку, конечный статус и число переходов. Не каждый возможный параметр любого сайта следует перенаправлять: это набор проверок демонстрации.

При необходимости повторить с User-agent поисковика: сайт может отвечать иначе. Из XML-карты убрать 404/закрытое. Параметрические дубли привести к осмысленной схеме; распознанное имя meta-директивы местами искажено, готовую строку по нему не копировать.

## 20:39–23:00. Дубли и достижимость

Кейс Романа Михальчука на Tilda: варианты со слэшем и без, по рассказу, делили запросы; приведение к одному адресу улучшило позиции. Это отдельный исторический пример, не указание менять все работающие URL. Сохраняется требование основной части об осторожности миграций.

Orphan-страницы не имеют входящих ссылок, поэтому могут не обнаруживаться. Большую глубину клика тоже считает препятствием. Ориентиры пятого/шестого уровней — его обобщение; важные страницы рекомендует связывать с главной и держать доступными за один-два перехода.

**Вход:** пул страниц и их текущее состояние. **Выход:** локализованная причина — обнаружение, запрет, код, дубли, рендеринг или достижимость — и соответствующее действие. **Приёмка:** нужное доступно и связано, удалённое/закрытое не объявлено в Sitemap, тестируется реальный ответ, индексирование отличено от доступа и результата стороннего парсера.
