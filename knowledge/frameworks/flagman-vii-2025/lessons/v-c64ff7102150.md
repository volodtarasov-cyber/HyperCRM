## 00:00–06:15. Ответы и источники обнаружения

В Response Codes разобрать редиректы, клиентские/серверные ошибки, недоступные скрипты и страницы. Ожидаемый код полезного обычного документа — 200. Слова в начале о закрытии остальных кодов передают упрощённую позицию лектора; конкретный редирект/ошибка разбираются по назначению, а не исправляются все в 200.

Обычный обход не обнаруживает URL без входящих ссылок. Для более полного списка подключить **Sitemap, Google Analytics и Google Search Console**, разрешить сбор/обход новых URL из этих источников. В демонстрации API авторизуются через аккаунт/токен, выбираются даты и метрики. Упомянутый интерфейс/версия Analytics относится к записи, точная современная интеграция не добавляется.

Во внешних ссылках проверить, куда и откуда они ведут; низ страницы **Inlinks / From / To** помогает найти источник. Неизвестная ссылка может быть своей старой статьёй или спам-комментарием — открытие страницы и исходника проясняет. Nofollow предлагает, если не хочет передавать вес; это трактовка автора.

## 06:15–12:25. Рендеринг, изображения, разметка

Включить JavaScript и нужное устройство, посмотреть сохранённое отображение. Полный рендеринг медленнее, лектор не обходит весь сайт ради одного визуального примера.

В Images отсортировать вес, при необходимости настроить порог и найти тяжёлые файлы. Обсуждает оптимизацию/формат WebP; величины — диагностические ориентиры записи, не универсальный норматив для любого изображения.

Структурированные данные сначала включить в настройках, затем **повторить обход**. Во вкладке нужных HTML проверить ошибки, предупреждения, типы и отсутствие разметки. Предупреждение об Organization в примере требует прочитать конкретное объяснение; не каждое замечание автоматически является критичной ошибкой.

## 12:25–20:51. URL, глубина и визуализация

Сортировка адресов и вкладка Parameters помогают найти параметры/непонятные варианты. Лектор предпочитает чистые ссылки, но применимость конкретных параметров определяется страницей — общий урок курса с полезными параметрическими URL остаётся отдельным исключением.

Site Structure показывает папки и уровни, Crawl Depth — число переходов. Визуализация дерева обхода помогает увидеть связи, разделы и закрытое. Предпочитает дерево круговой диаграмме; это удобство конкретного пользователя, не SEO-метрика.

Рекомендует важное держать близко к главной и рабочие страницы до четвёртого уровня. Объяснение о падении обхода после пятого Google/шестого Яндекса — обобщение лектора, не измеренный предел всех сайтов. Увеличение скорости краулера тоже учитывать по ресурсу сервера.

## 20:51–26:58. Без трафика и без входящих ссылок

Для Orphan Pages нужны источники Sitemap/Analytics/Search Console; без них обычный обход не доказывает отсутствие сирот. В демонстрации таких URL на своём сайте не находит.

Для страниц без трафика выбрать сессии Analytics и клики Search Console за **минимум три месяца**, лучше больше по его словам. Экспортировать в Excel, отфильтровать пустые/нулевые показатели и учесть индексируемость. За неделю/месяц считает данных недостаточно.

В примере выделяет старую нечитавшуюся статью, предлагает удалить с соответствующим кодом и убрать из Sitemap. Это решение его конкретного сайта. По другому смыслу он также допускает оптимизацию и добавление ссылок; отчёт формирует кандидатов для выбора действия. Отсутствующая интеграция, выбранный период и действительно измеренный ноль различаются.

## 26:58–31:09. PageSpeed и сниппеты

Подключить PageSpeed Insights API и повторить сбор, смотреть столбцы скоростей. Запросы ограничены по частоте и обход медленнее. Излишняя параллельность сама нагружает сайт и искажает показатели, поэтому лектор снижает поток.

Его высказывания о допустимых секундах и приоритете больших сайтов относятся к записи; не выдаются как общие нормативы пользовательской скорости. SERP Snippet показывает **предварительный вид** по заданным параметрам длины; не гарантирует, что Google реально выведет именно эти текст и оформление.

## 31:09–34:35. Robots и статическая карта

Можно загрузить/изменить robots в программе и испытать обход. Это тест конфигурации, не автоматическая замена файла сервера.

Для статичной Sitemap отобрать полезные HTML с 200 и без noindex, проверить прочие настройки, экспортировать карту и затем разместить. Уместно для небольшого/статичного проекта без собственной генерации; обновляющийся сайт требует соответствующего дальнейшего обслуживания карты.

**Вход:** настроенный обход и разрешённые данные консолей/аналитики. **Выход:** выборки ошибок, глубины, разметки, изображений, сирот и отсутствия трафика, при необходимости статичная карта. **Приёмка:** источники и период известны, данные реально получены, отчёты связаны с URL/источниками ссылок, решения об изменении страницы не подменены цветом предупреждения.
