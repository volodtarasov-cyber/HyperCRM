## 00:00–04:03. Семантика целевой страницы

Взять уже подготовленную семантику либо выгрузить видимость подходящего URL через Keys.so/Мутаген. Демонстрирует доступную выгрузку даже в ограниченном аккаунте Мутагена; это условия записи. Если данные только Яндекса, допускает использовать их для подготовки семантики даже при целевом Google.

В Excel отсортировать запросы по подходящей частотности, удалить явный мусор/чужие сервисы. По этому набору можно начинать измерение позиций целевой страницы. Это отделено от будущих информационных маркеров статей-доноров.

## 04:03–10:12. Идеи не равны подтверждённым темам

Запросить у ИИ информационные темы для ниши с пользовательским спросом. Полученный список — лишь идеи. Для каждой: название/суть в поиск → подходящая статья → видимость её URL → выбрать реальный маркер и отметить частотность.

Примеры: из «можно ли бурить зимой» получается «бурение скважин зимой»; для глубины выбирает «глубина скважины для питьевой воды»; для сравнения песчаной и артезианской смотрит несколько форм и признаёт неоднозначность. Историческую частотность оценивает вместе со смыслом, не доверяет подозрительному максимуму автоматически. Можно также искать темы непосредственно в видимости лидеров, но ИИ сокращает первоначальный поиск.

## 10:12–20:28. Анкор-лист из видимости

Взять запросы сильного сопоставимого конкурента по нужному URL как основу. Между текстовыми анкорами вставить URL-размещения; ориентир демонстрации — примерно два текстовых, один URL, около 70/30. Конечный набор дополнить брендом продвигаемой компании и значимыми связанными словами.

Через Just Magic → Акварель-генератор (либо ГАР) выделяет связанную лексику: артезианские, обустройство, известняк, песчаные и другие. Проверяет, что важное действительно есть в анкорах. ИИ просит лишь помочь с естественной формой фразы, когда термин непонятен.

Из заготовок **убирает «цена/купить»**, ссылаясь на естественность и оговорки предыдущего урока. Это уточнение конкретной ссылочной подготовки, не правило удалять цены с самого сайта. Бренд БИКС в примере — выбранный демонстрационный бизнес/конкурент, не бренд любого нового проекта.

Сравнивает полученный анкорный текст и страницу через ГАР, демонстрируя сходные облака. Это иллюстрация идеи внешнего документа, не измеренный последующий рост после размещения. Каждый анкор должен оставаться уместным, а не состоять из механического списка терминов.

## 20:28–26:45. От тематики к предварительному списку

Взять категории таблицы доноров Miralinks, отправить ИИ вместе с сайтом и просьбой выбрать близкие темы. В примере получает дом/строительство, производство, бизнес, технические системы. Сам впоследствии сомневается в исключении общих СМИ: считает, что они могут подойти почти любой теме.

По теме «дом» применяет показанные базовые фильтры: возраст больше трёх лет, DR больше пяти, хороший/отличный уровень, более десяти запросов топ-1. Отбирает 139 строк, копирует **в отдельную вкладку**, сохраняя исходную таблицу, сортирует по цене и убирает явно неподходящие расходы. Это параметры демонстрации, не доказанные общие пороги качества.

Два запроса к ИИ:

1. По списку URL оценить тематическую близость к нашему сайту и выбрать, например, 20 приоритетных доноров; при изучении страниц включить поиск.
2. По очищенной таблице тематик, возраста, метрик и цены предложить приоритетный набор.

Ответ модели сокращает список для просмотра, но не является достоверным обследованием донора.

## 26:45–34:59. Ручная проверка исправляет ИИ

В ответах появляются сайты о моде/праздниках, ошибочно объявленные строительными. Автор открывает их и исключает. Проверяет выбранное через Keys.so: динамику, реальные запросы/страницы, тематичность, затем внешний вид. Цена учитывается вместе с качеством: ограниченный сайт за 400 рублей может быть разумным кандидатом, а дорогой не гарантирует нужной отдачи.

В пример подходят ландшафт, загородная жизнь, дача, инженерные темы. Реальная статья про скважину должна выглядеть естественной для аудитории. Показатель «траст 9–10» внутри GoGetLinks не принимается достаточным основанием: у одной площадки хорошие биржевые оценки, но слабое содержание/видимость. Про другую автор, вопреки ожиданию, признаёт приемлемое состояние. Живая оценка не подгоняется под заранее объявленный вывод.

## 34:59–39:48. «Моя дача» и дальнейшая очередь

Для дачного донора видит подходящую семантику и просит ИИ оценить связь статьи с сайтом; модель советует экспертный гостевой материал. Числа 400/1000 рублей в обсуждении — пример цен записи, не текущий каталог. Точное написание доменов и их метрики не восстанавливаются по одному ASR-тексту.

Автор подозревает, что Qwen обрабатывает только часть большой таблицы. Предлагает другие модели либо порции по 40–50 сайтов с выбором лучших, затем ручной просмотр. Из выбранной категории можно собрать очередь 20–30 подходящих доноров, после перейти к другим близким темам. Его расчёт «на три месяца при десяти размещениях» — иллюстрация регулярности.

**Выход части 1:** семантика цели, подтверждённые информационные темы с маркерами, разнообразный анкор-лист и вручную просмотренные кандидаты-доноры. **Статья и фактическое размещение ещё не выполнены** — начинаются во второй части. **Приёмка:** ИИ-идеи проверены, чужие темы исключены, исходная таблица сохранена, бренд адаптирован, метрики не заменили ручной просмотр.

**Инструменты:** Мутаген, Keys.so, Excel, XMind как вариант, Qwen/другие ИИ, Just Magic/Акварель-генератор, ГАР, Miralinks, GoGetLinks.
