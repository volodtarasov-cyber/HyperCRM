# Базовая настройка KeyAssort и импорт выдачи

## Проект и поля — 00:00–00:08

Создать проект с понятным названием темы и региона. Импортировать файл: отметить строку заголовков, выбрать колонку фраз, назначить остальные поля строковыми или числовыми по содержимому. Файл из одной колонки не добавляет дополнительных параметров. Одинаковые сущности во всех выгрузках лучше называть одинаково — «Фраза», «URL Яндекс», «URL Google».

В общих настройках включить нужные рабочие колонки. Число главных полезно особенно для услуг; комментарии позволяют сохранять спорные решения. Остальные поля и экспорт топа включаются по необходимости, чтобы не перегружать вид.

Базовый демонстрационный режим — middle, сила 3. Это начальная настройка для дальнейшего подбора, не финальная рекомендация каждой нише. Отдельно существуют маркерная привязка, миграция между группами и расширение семантики.

## Глубина и исключения — 00:08–00:12

Автор предлагает обычно анализировать не глубже топ-20: для услуг и статей пробовать 20, для магазинов — 10 или 15. Настройку проверяют по теме. Один раз собранные данные можно повторно кластеризовать с разными параметрами без нового сбора выдачи.

Сервисы Яндекса, спектральные примеси и свой список доменов/URL можно исключать **из расчёта кластеризации**. Это не удаляет их из собранного SERP: в просмотре выдачи исключённые результаты остаются видны. В список можно добавить мешающие агрегаторы, например Авито или Профи. Для факультативной чистки через Яндекс Услуги исключение временно снимают — следующий урок.

Свежие результаты автор обычно оставляет; исключение допускает для заметно нестабильной выдачи. Это решение по конкретному состоянию, а не обязательная галочка.

## Сбор через XMLRiver — 00:12–00:19

В версии программы из записи встроенный сервисный сбор выполняется через XMLRiver. Для Google, выдачи Яндекса и частот используются разные адреса API; похожий хвост ключа не делает адреса взаимозаменяемыми. Указать регион/местоположение, язык, страну и при необходимости устройство. Для Google ID местоположения можно найти в справочном файле.

При сборе через сервис отдельные прокси и антикапча не требуются. Прямой сбор Google лектор не рекомендует из-за трудоёмкости и капчи. О вкладке XMLProxy в записи говорит как о неработающем и нестабильном сервисе; его состояние сейчас не проверялось.

Глубина оплачиваемого сбора и глубина последующей кластеризации — разные настройки. Лектор показывает тарифный пример: топ-10 — 20 ₽ за тысячу запросов, топ-20 — вдвое, топ-50 — впятеро. Это условия записи, не текущий прайс. При большом числе исключённых агрегаторов слишком мелкий SERP может оставить мало пригодных результатов; запас глубины оценивают до сбора.

Сохранить настройки, затем запустить нужный сбор и дождаться завершения. Число фраз с данными сопоставить с числом фраз проекта.

## Импорт готового SERP — 00:19–00:27

Альтернатива: снять выдачу в Key Collector или другом инструменте. В Key Collector выбрать экспорт поисковой выдачи нужной системы и глубины; для импорта достаточно двух колонок — фраза и URL выдачи. Частоты при наличии можно переносить отдельно. Сниппеты для этого шага не нужны.

В KeyAssort выбрать импорт поисковой выдачи. На предложение удалить существующие данные ответить «нет», если требуется сохранить проект и дополнить его SERP. Это существенная развилка: удаление может стереть ранее загруженные частоты и другие параметры.

Импорт выдачи сопоставляется с фразами, уже существующими в проекте. Дополнительные фразы из файла сами по себе не появляются. Проверить кодировку по читаемым примерам, колонки и итоговое покрытие. Недостающую выдачу **дособрать**; «пересобрать» используют, когда осознанно требуется обновить ранее полученные данные.

## Когда собирать частоты — 00:27–00:29

Статистика фраз — частоты Wordstat с выбранными операторами: базовая, уточнённая и точная. Лектор предлагает собрать их после кластеризации: к этому моменту будут удалены чужие товары, информационные фразы и прочий мусор. Показанные возможности прямого сбора через Директ относятся к версии программы в записи.

Вход: очищенный список и регион проекта; сервисный доступ либо готовый SERP. Выход: сохранённый проект с импортированными фразами, корректным региональным SERP и осмысленными исключениями. Приёмка: кодировка читаема; существующие поля не стёрты; покрытие выдачей проверено; исключение из расчёта не спутано с отсутствием в сыром SERP.

Инструменты: KeyAssort, XMLRiver, Key Collector; сравнительно упомянут XMLProxy. В уроке не требуется запускать платный сбор для обработки самого курса.
