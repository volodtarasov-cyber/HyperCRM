## Выбор темы и донора — 00:00–00:04

Вход — информационный маркер и таблица промптов. Для надёжного знакомого донора автор подбирает тему-мост, близкую и ему, и целевому сайту. Для пакета ещё не согласованных размещений допускает общую тему по маркеру: иначе после отказа площадки заточенная под неё статья может оказаться неудобной.

Один маркер можно разрабатывать разными статьями на разных донорах. На **одном доноре** автор не предлагает дублировать один и тот же кластер несколькими статьями. Если маркера нет, просит ИИ предложить темы, затем по подходящей теме смотрит поиск, конкретных конкурентов и их видимость.

## План и исходные показатели — 00:04–00:15

В примере Qwen предлагает название с маркером, затем пять основных разделов. Их количество связано с выбранной моделью и ожидаемым объёмом, а не общей нормой. Таблица подтягивает заполненные ручные поля в последовательные промпты.

Для текстовой релевантности автор собирает:

- глубину — три главных слова и ориентиры по медиане сопоставимых страниц;
- ширину — связанные слова, обычно достаточно смыслового включения;
- факультативно основные N-граммы, в примере первые пятнадцать из ГАР.

Связанные слова очищает от случайных служебных фраз, политики обработки данных и лишних призывов, которые могут привести к неуместному содержанию. Основной инструмент — ГАРпро.

Показанные альтернативы: JustMagic «Акварель» для ширины; МегаИндекс с вручную переданными конкурентами для глубины; Artur2k для облака и слов; Мирatext для анализа готового текста. Автор прямо говорит об ограничениях: МегаИндекс в его опыте дробит формы неудобно, а Miratext не даёт такой же полной проверки ширины/N-грамм. Эти инструменты не объявляются точными заменами всех функций ГАР.

Числа для Qwen автор иногда задаёт с запасом относительно медианы, потому что модель не всегда выполняет счёт. Это практический приём конкретной модели; фактический текст затем измеряется.

## Поэтапная генерация и повторное измерение — 00:15–00:25

Сначала написать введение с исходными требованиями, затем последовательно разделы. Сохранять в редакторе/HTML, не полагаясь только на вид ответа в чате. В примере без заключения получилось около 12,5 тысячи знаков вместо задуманных двадцати, таблицы модель не добавила.

Проверить полученный текст анализатором. Для ГАР передать HTML текста в исходно созданную проверку. По результату составить отдельный промпт заключения: недостающие слова/формы и ширина, а также запрет на дальнейшее усиление уже избыточного. Добавить заключение и проверить снова.

Личное правило автора — до пяти вариантов заключения в том же чате. Если базовая статья плоха целиком, проще новый чат и генерация заново по уже подготовленным вводным. Не пытаться вместить весь недостающий словарь механическим перечнем в конец.

В показанном результате автор принимает показатели ГАР около 99 по ширине и 80 по глубине. Это его критерий конкретного примера, не универсальный проходной балл. Итог около 15 тысяч знаков принимает без обязательного наращивания до двадцати; при необходимости отдельный раздел можно превратить в таблицу с помощью ИИ. Само отсутствие обещанных таблиц не скрывает.

## Ссылка и метатеги — 00:25–00:30

В том же контексте статьи передать точный URL и анкор, получить нативное предложение, поправить падеж и вставить ближе к началу, в примере в конце введения. Сверить сам адрес, особенно punycode: модель способна исказить символ.

Подготовить title, description и анонс. Для важных страниц и дорогих доноров автор предпочитает ГАР, в остальных случаях допускает промпт. Если модель вместо трёх отдельных полей выдала одно предложение, ответ исправляют, а не принимают по факту генерации.

## Корректура, изображения и автор — 00:30–00:37

В новом чате передать всю статью и последовательно запросить проверку орфографии, повествования и нежелательных/проблемных упоминаний, которые в таблице автор называет «законностью». Это ИИ-проверка учебного процесса, а не полученное юридическое заключение. Автор исправляет прежде всего явные ошибки падежей, сочетаний и бессмысленные перечни; не каждое стилистическое замечание принимает. Найденное удобно искать `Ctrl+F`.

Для иллюстраций предлагает удобный генератор, формат 16:9 и примерно пять-шесть картинок для длинного материала; в видео использует четыре ради времени. Сохраняет свою оговорку о коммерческих условиях генератора. Фотохостинг должен давать постоянный прямой адрес без скорого автоудаления. Название показанного хостинга в транскрипте не установлено, Imgur назван как альтернатива.

Картинки распределить по статье, выставить подходящую ширину/высоту, добавить описательные тематические alt. Фотореализм автор не считает обязательным; учитывает приёмку конкретного донора.

В конце — блок об авторе/компании для укрепления бренда. Если правила площадки позволяют, дополнительная ссылка на страницу автора. Наличие второго URL не предполагается для каждого донора.
