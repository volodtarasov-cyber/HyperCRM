## 00:00–08:15. Кому нужен XXL-вариант

Дополнительный процесс для темы, где базового расширения мало. Пункты со звёздочками факультативны; больше источников — глубже сбор, но больше обработки. Демонстрация на услугах бурения.

В Keys.so задать основной запрос и получить дополняющие фразы. При широком наборе услуг повторять по направлениям. Для сбора лектор предпочитает крупную базу **Яндекс Москва**, затем чистку частотностями своего региона. При региональных особенностях добавить местную базу: типы грунта, условия и услуги отличаются. Это отличается от проверки выдачи при кластеризации, где в основном процессе нужен целевой регион.

Дополнительно взять Google: в примере около 2987 против 1984 фраз Яндекса, но цифры относятся к записи. Наличие разных наборов — причина не считать один источник исчерпывающим.

## 08:15–21:43. Собрать базисы и расширить их

Базисы обычно двух-трёхсловные, иногда однословные для узкой темы. «Краны» для кухонных смесителей слишком широко: приведёт строительную технику и иной мусор.

В исходных отчётах отобрать два и три слова, по необходимости ограничить похожесть. В демонстрации пробует пороги 5–10%; не объявляет один обязательным. Собрать Яндекс/Google-варианты, удалить неявные дубли встроенным инструментом, бегло убрать явно чужие направления/бренды. На этом этапе согласованность формы не принципиальна — это вход расширения, а не готовые заголовки.

Сохранить базисы в Excel/Блокноте. Подать в **расширение ключевых слов**, добавить хвосты. Пример порога похожести 30, при мусоре 40; 50 может потерять часть полезного. Google-итерация факультативна.

## 21:43–34:31. Обязательное расширение конкурентами

Основное направление шире одной услуги: бурение связано с обустройством, обслуживанием и другими реальными задачами. Открыть список конкурентов и вручную проверить бизнесы, а не просто отметить домены с максимальным объёмом. Исключить несопоставимые платформы и фиксировать заведомо чужие услуги как будущие исключения. Кессон, например, нельзя выбросить вместе с отоплением только по соседству слов — он может относиться к обустройству.

Составить список подходящих доменов с видимостью и сформировать **групповой отчёт**. Обычный отчёт одного URL не заменяет этого действия. Дополнительно повторить Google, объединить и удалить повторяющиеся домены. Sitemap/заголовки конкурента можно использовать как альтернативный источник, учитывая страницы без спроса и неполноту набора.

Сохранять списки и понятно называть отчёты. В нескольких вкладках изменение поисковой базы/региона может затронуть другой открытый отчёт. При подозрительном совпадении количества запросов перепроверить настройки, а не считать, что две базы обязательно идентичны.

## 34:31–43:25. Факультативные Мутаген и МегаИндекс

В Мутагене показывает:

- «Генератор / Супергидра» по списку доменов; в примере вес ключа около 3 и топ 15–20.
- Расширение семантического ядра по базисам, исключение исходных фраз.
- Массовое получение хвостов по списку.

Это дополнительные источники, не требование получать огромный массив любой ценой.

В МегаИндексе: подбор/кластеризация → расширение запроса похожими; отдельно сбор по доменам. При необходимости использовать органику Яндекса/Google и рекламные базы Директа/Google Ads. Скачать результат кнопкой внизу отчёта; при нечитаемой кодировке переключить UTF-8/Windows-1251, разделитель сохранять осмысленно. Разные отчёты в демонстрации ведут себя неодинаково.

## 43:25–49:55. Подсказки и реклама

Keys.so → сбор поисковых подсказок: подать базисы, выбрать нужный регион, при лимите разделить на части. В показанном интерфейсе список регионов шире основной базы. Глубину итераций лектор точно не устанавливает, лишь предполагает по результату — её нельзя выдавать за гарантированный параметр.

Подсказки сохранить и добавить к остальному. В Мутагене дополнительно доступны рекламные запросы по ключу/домену; базу рекламы предварительно оценить на мусор. Другие сервисы тоже допускаются при необходимости глубины.

## 49:55–62:52. Объединение без потери данных

Основой служит **групповой отчёт Keys.so по доменам**. В него добавлять запросы из буфера/файлов, сохраняя единый пул. Удобный надёжный способ — скачать каждый источник в папку с ясными названиями, затем последовательно импортировать. Копирование быстрее, но легко потерять вкладку/источник; начинающему советует сохранение.

Обсуждает лимиты выгрузки до 100 тысяч и добавления списком около 10 тысяч в показанных условиях. Большой файл около 52 тысяч в итоге принимается, но работает медленно; TXT с одним списком и разбивка порциями стабильнее. **Успешное принятие файла в примере не означает отсутствие лимитов любой подписки.**

Не путать количество добавленных исходных фраз с количеством новых фраз отчёта: часть уже есть или не совпадает с данными конкурентов. Одинаковое число после импорта может требовать проверки источников/настроек, а не автоматического признания потери.

## 62:52–71:03. Минимум и завершение

Минимальный маршрут: расширить основной запрос → подобрать конкурентов Яндекса → создать групповой отчёт → объединить запросы; подсказки добавляются быстро по желанию. Остальные базы/базисы нужны по недостаточности результата.

По мере повторных источников прирост обычно меньше, но редкие новые запросы могут быть важны. Финальный большой массив ещё не готов для страниц: ожидается существенная чистка. Оценку будущих 3,5–4 тысяч коммерческих фраз после большого сбора лектор даёт как ориентир демонстрации, не завершённый результат этого урока.

**Вход:** тема, основной запрос, бизнес-ограничения и региональные особенности. **Выход:** сохранённые исходники, базисы/домены и объединённый пул запросов для чистки. **Приёмка:** источники не потеряны, настройки поисков/регионов проверены, обязательное отличено от факультативного, черновой массив не выдан за итоговую семантику.

**Инструменты:** Keys.so, Мутаген/Супергидра/хвосты, МегаИндекс, поисковые подсказки и рекламные базы, Excel, Блокнот/Notepad++.
