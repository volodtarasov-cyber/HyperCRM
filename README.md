# HyperCRM — операционная память маркетингового агентства

## Что это

Рабочая система на Codex + Obsidian + Google Sheets: держит актуальный контекст агентства, помогает управлять путём от трафика до денег и превращать результаты проектов в повторяемые механики, инструкции и программы.

**Задачи живут в YouGile** (с 2026-05-13). Vault — не задачник, не дневник и не история всех разговоров. В активном слое остаётся только информация, которая меняет следующие решения.

## Для кого

Сейчас — рабочая система Володи и агентской команды. Цель бизнеса — делегируемое агентство с 1 млн ₽+ чистой прибыли в месяц. Онлайн-школа, клуб и курсы со спикерской ролью Володи не являются активными направлениями.

## Команды

| Что сказать | Что произойдёт |
|-------------|---------------|
| «зафиксируй решение» | Запись в `life/decisions.md` (стратегия) или в `hypotheses.md` проекта |
| «зафиксируй гипотезу» | Запись в `agency/hypotheses.md` или `clients/<клиент>/hypotheses.md` |
| «статус [клиент]» | Строка в реестре + карточка клиента + свежие результаты |
| «неделя» / «ретро» | Недельный обзор **по запросу** — собирается из материалов, не из дневника |
| «отчёт в десятку» | Помощь собрать черновик; дедлайн вс 23:59 Володя помнит сам |
| «отчёт для [клиент]» | Клиентский отчёт по трафику |
| «разбери inbox» | Раскидать записи из `inbox.md` по нужным файлам |

## Быстрый захват

Файл `inbox.md` в корне — свалка для мыслей, идей, ссылок.
Разбирается по запросу.

## Структура

Подробно — в `CLAUDE.md`. Кратко:

```
HyperCRM/
├── CLAUDE.md             ← мозг системы
├── README.md
├── inbox.md              ← быстрый захват
├── agency/               ← БИЗНЕС: модель, план, финмодель, рынок, гипотезы
│   ├── product/boxes.md    ← каталог продуктовых единиц
│   ├── cases/              ← кейсы для продаж
│   └── leadgen/            ← собственный лидген агентства
├── clients/              ← КЛИЕНТЫ: кого ведём и на каких условиях
│   ├── _index.md           ← ★ реестр: клиент × единица → цена, исполнитель, данные
│   ├── _template/          ← стандарт клиентской карточки
│   └── <клиент>/           ← карточка, results/, access.md 🔒
├── marketing-os/         ← МЕТОД: как делаем работу
│   ├── core/               ← канон и единый словарь терминов
│   ├── routes/             ← OPF и полная диагностика
│   ├── engines/            ← переиспользуемые методы
│   ├── playbooks/          ← прикладные механики
│   ├── templates/          ← шаблоны метода
│   └── evidence/           ← проверяемые применения
├── team/                 ← роли, оплата, подрядчики
├── life/                 ← decisions.md, ten-report/, финансы
├── knowledge/            ← фреймворки (JTBD, Hormozi, RDB, Шварц, AARRR)
├── projects/             ← прочее: seo-sites/, ai-infobiz/ (закрыто)
└── system/
    ├── changelog.md      ← только актуальные изменения самой системы
    ├── templates/        ← шаблоны (актуальные)
    └── migrations/       ← разовые миграции (YouGile export и т.д.)
```

### Правило: где живёт клиент

| Условие | Где |
|---|---|
| Продаём услуги — приток, посадочная, карточки, измерение | **здесь**, карточкой в `clients/` |
| Строим маркетинг и продажи целиком, и сотрудники клиента работают внутри системы | в **собственном репозитории клиента**; здесь — только карточка уровня клиента и данных |

Первый случай второго рода — Левша: полный маркетинг в отдельном репозитории на macOS, внутренние материалы вынесены в `D:\SecondBrain\_archive\levsha\`.
