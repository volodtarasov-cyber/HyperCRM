# Agency OS — библиотека маркетингово-операционных модулей

**Статус:** active — методологическое ядро
**Владелец:** Володя

> **Текущая роль:** универсальное методологическое ядро, а не отдельный бизнес-проект. Модули применяются в CMO-проектах, превращаются в материал клуба/обучений и могут стать производственным слоем делегируемого агентства. Рост агентства допустим только при выполнении фильтра делегируемости из `life/decisions.md`.

## Что такое модуль

Модуль — это не отдельная услуга и не абстрактная идея. Это повторяемая связка:

```text
ниша / задача
→ оффер
→ канал
→ посадочная / объявление / касание
→ обработка заявки
→ CRM / учет
→ follow-up
→ отчетность
→ повторная продажа или следующий шаг
```

Цель модуля — быстро развернуть управляемый путь:

```text
заявка → обработка → продажа → повторная продажа → прибыль
```

Над библиотекой модулей находится единый продуктовый каркас:
[Коммерческая система для сервисного бизнеса](service-business-commercial-system.md).

публичный сайт, клиентский Command Center, каноническая модель данных,

## Зачем это нужно

Система нужна, чтобы не изобретать маркетинг заново для каждого клиента.

Вместо "настроим Директ / Авито / CRM" мы накапливаем библиотеку готовых growth-модулей:

- под конкретные ниши;
- под конкретные боли;
- с понятными артефактами;
- с метриками;
- с условиями применения;
- с рисками и ограничениями.

---

## Правило добавления модулей

Модуль попадает в библиотеку, если есть хотя бы один из признаков:

- его уже применили на клиенте;
- его завтра реально запускаем;
- он повторится минимум в 2 клиентах / нишах;
- он может стать частью партнерства с оператором;
- он экономит время команды при следующем запуске.

Не добавляем сюда общие идеи без следующего действия.

---

## Статусы

```text
draft       — гипотеза, еще не запускали
pilot       — запускаем на первом клиенте
working     — показал первые результаты
playbook    — можно повторять на следующем клиенте
retired     — больше не используем
```

## Как использовать

1. При работе с клиентом сначала определить, какая утечка главная:
   - нет заявок;
   - заявки есть, но плохо обрабатываются;
   - клиенты не доходят;
   - нет повторных продаж;
   - нет аналитики;
   - слабая упаковка.
2. Выбрать 1-2 модуля, не больше.
3. Развернуть их в клиенте.
4. Зафиксировать факт запуска, цифры, ошибки и артефакты.
5. После первого результата обновить модуль до `working` или `playbook`.

## Ритуал обновления

Раз в неделю, перед ten-report или после него:

```text
1. Что из сделанного на неделе можно превратить в модуль?
2. Какой модуль продвинулся по статусу?
3. Какие артефакты появились?
4. Какие цифры стоит сохранить?
5. Что можно повторить на следующем клиенте?
```

Это должно занимать 10-15 минут, не отдельную большую сессию.
