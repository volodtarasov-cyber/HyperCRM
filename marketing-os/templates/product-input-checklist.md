# Чек-лист входных данных под продукт

> Что собрать, чтобы прогнать **один продукт/юнит** по цепочке диагностики ([карта процесса](../routes/full-business-diagnostic/diagnostic-process-map.md)). Заполняется фактами из учёта.
> Компания собирается один раз ([профайл](company-profile-template.md)); это — **на каждый продукт**.
> Гард-рейл: нет данных → `[нет данных]`, не выдумывать.

## 1. Продукт
- [ ] Что входит, пакеты/зоны, из чего собирается чек.

## 2. Экономика юнита (из учёта)
- [ ] Средний чек · частота · маржа · объём (нарядов/мес) · доля в выручке · прайс по вариантам.

## 3. Спрос
- [ ] Поисковые запросы по продукту **+ объёмы** (Wordstat).
- [ ] Сезонность по продукту.

## 4. Конкуренты по этому продукту ⚠️ критично
- [ ] Кто прямые конкуренты именно по этому продукту.
- [ ] **Их негативные отзывы** (2–3 конкурента, по 10–20 отзывов) — из них барьеры и точки слома.

## 5. Клиенты юнита — JTBD-сырьё
- [ ] Типажи покупателей, триггеры.
- [ ] **Дословные фразы** клиентов про продукт (отзывы, звонки, переписки): что хотят, чего боятся, возражения, причины отказа.

## 6. Путь клиента — для CJM
- [ ] Как находят (каналы), как обращаются.
- [ ] SLA ответа, реальные сроки работ, как обрабатывают заявку.
- [ ] Что есть на каждой точке контакта (карточка, скрипт, расчёт).

## 7. Доказательства
- [ ] Кейсы / фото до-после · гарантия · материалы — по продукту.

## 8. Продажи
- [ ] Конверсия заявка→сделка (если считается) · кто продаёт · есть ли скрипт.

## 9. Цель по юниту
- [ ] Зачем диагностируем: загрузить мощность / поднять чек / лидген / удержание.

---
**Минимум для старта:** 1, 2, 4 (хотя бы негатив конкурентов), 9. Остальное добирается по ходу, пробелы метятся `[нет данных]`.
