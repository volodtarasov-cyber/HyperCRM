# Шаблон: скоркард зрелости коммерческой системы

> Переиспользуемый шаблон для оценки зрелости маркетингово-продажной системы бизнеса по 7 осям одной цифрой. Даёт приборную панель прогресса: где мы и растём ли. Пересобирать **раз в квартал**.
> Часть метода [screening-to-strategy-diagnostic](../routes/full-business-diagnostic/screening-to-strategy-diagnostic.md) и скилла `business-diagnostic`. Заполненный пример — `projects/detailing-samara/_scorecard-*.md`.

---

## Как пользоваться

1. По каждой из 7 осей выставить балл 0–100% по рубрике ниже.
2. Записать **обоснование** (на какие факты/артефакты опирается балл) и **что двинет вверх**.
3. Общий балл — среднее (или взвешенное, если оси не равны для бизнеса).
4. Через квартал — пере-замер. Смотрим, какие оси сдвинулись.

**Балл — не самооценка «нравится/нет», а привязка к артефактам.** Нет скрипта продаж — ось «Продажи» не выше 40, как бы хорошо ни продавал один человек.

---

## 7 осей

| Ось | Что меряет |
|---|---|
| **1. Лидген** | управляемый поток целевых заявок на маржинальные услуги |
| **2. Оффер / упаковка** | оффер, линейка пакетов, позиционирование, доказательства |
| **3. Продажи** | конверсия заявки в сделку, скрипты, апсейл — системно, не на одном человеке |
| **4. Удержание** | второй визит, повторные продажи, своя база |
| **5. Измерение** | аналитика, колл-трекинг, атрибуция, поля CRM |
| **6. Контент / доказательства** | кейсы, фото/видео, банк работ |
| **7. Репутация** | отзывы, NPS, ответы, рейтинг |

---

## Рубрика баллов (общая логика на каждую ось)

```text
0–20    нет / хаос: процесса нет, держится на случайности
21–40   зачатки: что-то есть, но не система и не у всех
41–60   собрано, не внедрено: есть артефакт/регламент, но в работе слабо
61–80   работает: внедрено, даёт результат, измеряется
81–100  система: повторяемо, на команде, улучшается по циклу
```

Конкретику под ось доопределять под бизнес. Примеры якорей:

- **Продажи 40** = продаёт хорошо один человек, скрипта нет, конверсия не считается.
- **Продажи 70** = скрипт есть, команда по нему работает, конверсия осмотр→сделка измеряется.
- **Удержание 20** = продали и забыли, второго касания нет.
- **Удержание 60** = маршрут второго визита собран, но ещё не запущен.
- **Измерение 30** = финансы ведутся, маркетинг (источник/CAC) — нет.

## Гард-рейлы
- Балл привязан к артефактам, не к ощущению.
- Цифры бизнеса (выручка, чек, CAC) берём из учёта (1С/CRM), не из прикидок.
- «Собрано, не внедрено» (41–60) — самая частая ловушка: артефакт есть, в операционке нет. Не путать с «работает».
