# Карта процесса диагностики — логика всей системы

> Как устроена вся цепочка: вход → анализ → выход, что каждый шаг потребляет и производит, и как шаги ссылаются друг на друга. Капстоун над [методом](screening-to-strategy-diagnostic.md), [спеком скрининга](../../engines/screening-analysis-spec.md) и модулями.

## Принцип №1 — на продукт, не на компанию
Один **продукт/юнит** (плёнка / шумка / полировка…) = одна полная цепочка. У каждого свой клиент, спрос, конкуренты, путь. Несколько продуктов = несколько прогонов. Компания (бренд, команда, бюджет, CRM, репутация) — **общий контекст**, собирается один раз.

## Принцип №2 — генеративно, не шаблонно
Скиллы кодируют **как думать**: всё цитирует данные по ID, экономика проверяется на сходимость, барьеры берутся из реальности (негатив конкурентов + VoC), вывод полный (лид-магниты, каналы, конфликты, приоритеты), есть планка качества. «Думай так», не «заполни поля».

## Цепочка: что потребляет → что производит

```
[ВХОД]
  /company-profile  ──→  профайл компании (1 раз): услуги, экономика, УТП,
                         команда, каналы, точки контакта, репутация, CRM, цели
  + данные по продукту (input-checklist): экономика юнита, спрос+Wordstat,
                         конкуренты и их НЕГАТИВ, VoC, путь/SLA, доказательства, цель

[АНАЛИЗ — на продукт]
  1. /screening    ──→  нумерованная модель параметров (5.2, 3.4…) +
                         записка 7 вкладок (Диагностика · Выводы · Рынок ·
                         Сегмент · План · Зоны внимания · Приоритет)
                         = ГЛАВНОЕ ОГРАНИЧЕНИЕ + план тактик (артефакт·метрика·риск)

  2. /jtbd-segments ──→  5–7 сегментов по работам: Core/Big Jobs, критерии,
                         опыт А/Б, ТОЧКА СЛОМА (из негатива конкурентов),
                         спрос с объёмами, готовность, сложность убеждения,
                         приоритизация (ядро / быстрые деньги / не первым)

  3. /cjm          ──→  по сегментам — путь ~8 шагов; на КАЖДЫЙ шаг:
                         эмоция(балл+лейбл) · барьеры · диалог(цитаты) ·
                         запросы(15+, по стадии) · лид-магниты(тип·Снимает·
                         канал по тёплости·альтернатива) · точка перелома;
                         + green/red конфликты сегментов + 5 сквозных приоритетов

  4. Скоркард      ──→  балл зрелости 7 осей (лидген/оффер/продажи/удержание/
                         измерение/контент/репутация) — приборная панель

[ВЫХОД — куда втекает]
```

## Кросс-ссылки (паутина, а не линия)
Это то, что делает анализ связным, а не набором отдельных кусков:

- **Негатив конкурентов** → точка слома (JTBD) = барьер (CJM). Один и тот же факт в трёх местах — если расходятся, ошибка.
- **Барьеры CJM по шагам** → темы кейсов/контента, блоки лендинга, ответы в скрипте продаж.
- **Запросы CJM по шагам** → контент-план и SEO-структура (запрос привязан к стадии воронки).
- **Лид-магниты CJM по шагам** → производство контента + распределение по каналам (канал = тёплость шага).
- **Точка перелома CJM** → туда максимум: доказательства + [диагностическая продажа](../../engines/diagnostic-sale.md).
- **🔴 Конфликты CJM (цена/скорость)** → раздельные пакеты и месседжи ([дизайн оффера](../../engines/offer-packaging-design.md)).
- **🟢 Единые решения CJM** → сквозные регламенты на весь центр (фиксация цены/срока, фотоотчёты).
- **After-этап CJM** → [маршрут удержания](../../playbooks/reactivation-old-base.md).
- **План скрининга** → приоритеты внедрения; **зоны внимания** → что проверить до действий.

## Куда уходят выходы (от анализа к делу)
| Выход анализа | В какой модуль/артефакт |
|---|---|
| Сегменты + Core Jobs | оффер, позиционирование, тексты |
| Точка слома / барьеры | доказательства, кейсы, скрипт |
| Конфликты сегментов | раздельные пакеты (оффер) |
| Лид-магниты по шагам | контент-производство, кейс-система |
| Запросы по шагам | контент-план, SEO |
| Точка перелома | диагностическая продажа |
| After-этап | удержание / постсервисный маршрут |
| План + приоритет | что внедрять и в каком порядке |
| Скоркард | измерение прогресса (квартал) |
